Fast and Anchor Training in the Supervised Codebase

Explanation of how /Users/shamane/Documents/comm-eff-ft/sim_v2 runs the paper-style fast masked circuit and slow unmasked anchor circuit, including how batches are sampled and passed between ranks.

In comm-eff-ft/sim_v2, this is one distributed training run, not two independent training jobs. It is launched as one torchrun --nproc-per-node=8 job on a single 8 GPU node. 

8 GPU single node
ranks 0..6: fast training circuit
rank 7: slow anchor circuit

The model used by that simulator is unsloth/Llama-3.2-1B, about 1.2B parameters. Every GPU holds a full model replica. There is no real pipeline slicing in sim_v2; pipeline activation compression is simulated by forward hooks on selected decoder layer outputs.

Process Roles

Fast Ranks: 0..6

These are the only ranks that own the actual training trajectory. They run masked supervised forward/backward, apply spectral correction when an anchor prior is available, average gradients across the fast group, and step AdamW. 

fast rank step:
  sample current batch
  masked forward
  backward
  spectral correction if anchor prior exists
  all-reduce across ranks 0..6
  optimizer.step()

Anchor Rank: 7

This rank does not maintain its own optimizer trajectory. It waits for rank 0 to send stale weights and a stale batch, loads those weights, runs one unmasked forward/backward, and sends selected clean gradients back to rank 0. 

anchor rank cycle:
  wait for stale packet from rank 0
  load stale weights
  unmasked forward/backward on stale batch
  send selected gradients back

Data Loading

The simulator does not use a PyTorch DataLoader in the usual epoch/iterator sense. It builds a flat token stream and samples random offsets into that stream.

Dataset Formatting

For the QuALITY setup, each dataset row is formatted as text: 

<article>

Question: <question>
A) <option 0>
B) <option 1>
C) <option 2>
D) <option 3>
Answer: <correct letter>

[EOS]

Then the code tokenizes all formatted examples and concatenates them: 

QuALITY train rows
  -> format as text
  -> tokenize
  -> concatenate into one long train_stream

QuALITY validation rows
  -> format as text
  -> tokenize
  -> concatenate into one long val_stream

Batch Sampling

Every fast rank samples its own mini-batch independently by calling: 

inp, tgt = get_batch(train_stream, micro_batch_size, seq_len, device, g_train)

Internally, get_batch() chooses random start offsets: 

stream: [token0, token1, token2, ... tokenN]

sample random start positions:
  s1, s2, ...

input batch:
  stream[s1 : s1 + seq_len]
  stream[s2 : s2 + seq_len]

labels:
  input_ids.clone()

It is standard causal language-model training. The Hugging Face model shifts labels internally when called with labels=input_ids.

How Batches Flow Through Fast and Anchor

Each fast rank samples current data from the same flat token stream, but with a rank-specific random generator seed. 

rank 0 samples current batch_0_t
rank 1 samples current batch_1_t
rank 2 samples current batch_2_t
...
rank 6 samples current batch_6_t

Rank 7 does not sample from the data stream. It has no independent active dataloader. It only receives stale batches from rank 0.

Rank 0 Staleness Queue

Rank 0 has an extra responsibility: it stores copies of its own old batches together with weight snapshots. 

rank 0 pushes into StalenessQueue:
  source_step
  full trainable weight snapshot
  rank-0 input batch
  rank-0 labels

After the configured delay, usually K = 20, rank 0 pops the old packet and sends it to rank 7. 

rank 0 -> rank 7:
  stale input batch
  stale labels
  stale weight snapshot

The anchor gradient is therefore a clean gradient on a stale sample from the same training distribution. It is not the full combined 7-rank fast batch. In the simulator, that is acceptable because the anchor prior is a stochastic clean geometry estimate, not a direct optimizer update.

Why There Is a K Value

K is the anchor staleness measured in fast optimizer steps. It exists to model the latency of the slow unmasked circuit. While the anchor is pulling a weight snapshot, running the expensive unmasked forward/backward, and returning gradients, the fast masked circuit keeps making progress.

If the fast circuit can complete about 20 masked optimizer steps during one anchor cycle, then the clean anchor gradient that arrives now was computed from weights and data that are about 20 fast steps old. That is why the simulator commonly uses K = 20.

Step 20 Rank 0 saves weights_20 and batch_20_rank0 into the stale queue.
Steps 21-39 Fast ranks keep training on current masked batches.
Step 40 Rank 0 sends weights_20 and batch_20_rank0 to the anchor.
After Arrival The returned clean gradient refreshes the spectral correction state.

Does Correction Happen Every Optimizer Step?

Once at least one anchor prior has arrived, the fast path can apply correction on every masked optimizer step. Anchor gradients arrive only periodically, but the spectral basis they update is cached and reused. 

each fast optimizer step:
  run masked forward/backward
  produce current masked gradient

  if a new anchor gradient arrived:
    update anchor EMA
    recompute spectral basis

  if a spectral basis exists:
    correct current masked gradient using cached basis

  all-reduce corrected gradients across fast ranks
  optimizer.step()

So there are two cadences:

  • Anchor cadence: how often the clean unmasked geometry is refreshed, for example every 20 fast steps.
  • Optimizer cadence: how often the fast masked gradients are corrected and stepped, which is every fast training step after a usable spectral basis exists.

Figurative Training Loop

Fast circuit, ranks 0..6, every optimizer step

1. Sample Each fast rank samples a current batch from the flat token stream.
2. Masked F/B Forward hooks mask selected decoder layer outputs; backward inherits the same mask.
3. Correct If a cached anchor basis exists, project and blend the current fast gradient.
4. Sync Average corrected gradients across fast ranks.
5. Step AdamW updates the fast model trajectory.

This row runs on the critical path. It owns the final model.

Rank 0 queue and anchor refresh, every K/cadence steps

A. Snapshot Rank 0 stores current trainable weights plus its current batch.
B. Wait K The packet stays in the queue until it is K fast steps old.
C. Send Rank 0 sends stale weights and stale batch to rank 7.
D. Anchor F/B Rank 7 loads stale weights and runs unmasked backward.
E. Refresh Returned gradients update the spectral EMA/SVD cache used by future fast steps.

This row refreshes the correction state. It does not run its own optimizer step.

Fast Step Fast Ranks 0..6 Rank 0 Extra Work Anchor Rank 7
20 Train on current per-rank batches with masking. Save weights_20 and batch_20_rank0. Waits or receives no-work control packet.
40 Train on current per-rank batches with masking. Pop weights_20 and batch_20_rank0, send them to rank 7, then save weights_40 and batch_40_rank0. Load weights_20, run unmasked backward on batch_20_rank0, return selected gradients.
41+ Continue masked training. Use the refreshed spectral basis when applying correction. Broadcast spectral state to fast ranks when updated. Waits for the next stale packet.

What Is Shared and What Is Independent

Component Fast Ranks Anchor Rank
Process Separate Python processes, ranks 0..6. Separate Python process, rank 7.
Model Full Llama-3.2-1B replica per GPU. Full Llama-3.2-1B replica, overwritten by stale snapshots.
Data source Same tokenized train stream, independent random batches per rank. No active independent sampler; consumes stale rank-0 batches.
Masking Enabled after warmup on selected decoder layers. Always disabled for anchor backward.
Optimizer AdamW steps every fast step. No optimizer step.
Output Owns the final trained model trajectory. Only returns gradients used to update spectral correction state.

Important Mental Model

This is not two independent training runs. It is one distributed run with two roles. The fast circuit owns training. The anchor circuit is a stale, unmasked gradient oracle that is periodically refreshed from the fast model and the fast data distribution. 

same torchrun job
same dataset/token stream
fast ranks independently sample current batches
rank 0 queues old copies of its own batch plus weights
anchor rank consumes only those stale queued batches
anchor returns clean unmasked gradients
fast ranks use those gradients as spectral priors
only fast ranks perform optimizer updates

Why This Matters for the verl GRPO Port

In verl, the anchor should follow the same idea, but the stale batch must be the already-processed actor mini-batch, not raw prompts. That actor mini-batch contains GRPO fields such as old_log_probs, advantages, response_mask, and optionally ref_log_prob. The anchor should run the same actor ppo_loss on that stale mini-batch. It should not regenerate responses, recompute rewards, or switch to an SFT loss.
