Strict Micro-Batch-1 Count

Verdict
For communication-efficient PPO/GRPO simulation, every actor FSDP forward inside the trainer update must be masked: the old-log-prob forward, the current-policy train forward, and any checkpoint replay inside the masked train backward region. The mask must be keyed by global step and token/activation identity, not by forward call. If one path is dense, or if each path samples a different mask, exp(log_prob - old_log_prob) compares different subnetworks.
Scope Count Meaning
Per trajectory 2 actor forwards 1 old-log-prob forward producing old_log_probs, then 1 train forward producing current log_probs for PPO loss.
Per global step, all DP ranks 2048 actor FSDP micro-forwards 1024 old-log-prob micro-forwards + 1024 train micro-forwards, with per-GPU micro-batch size 1.
Per rank 2048 / dp_size For 4 GPUs: 512 per rank. For 8 GPUs: 256 per rank.
Required masked full forwards 2048 per global step Hard rule for this research setup: all trainer actor micro-forwards should be masked. This is 2 per trajectory, plus any checkpoint replay inside train backward. The reference path is skipped here.

FSDP DP Division

Question Answer
What is DP here? Actor FSDP data-parallel size is world_size / ulysses_sequence_parallel_size. This launcher uses SP=1, so DP equals NGPUS_PER_NODE: 4 on 4x H200, 8 on 8x H200.
Is FSDP pure DDP? No. FSDP shards parameters, gradients, and optimizer state. But it is still data-parallel for batch flow: each rank receives different trajectories and runs the same forward/backward program.
How are trajectories assigned? The driver chunks the 1024-trajectory DataProto evenly along batch dimension. It is deterministic/even after any trainer batch balancing, not random assignment.
Why divide by DP size? Only for per-rank local forward counts. Global actor micro-forwards remain 2048. Per rank they are 2048 / dp_size, run in parallel across ranks.

Symbolic Mask Rule

trajectory z = (prompt_index i, rollout_index r)
token position = s
masked boundary/layer = b
hidden channel = c
global step = t

Good key:
M_t(z,s,b,c) = BernoulliKeep(seed, t, z, s, b, c)

Forbidden key terms:
forward_call_id, ppo_minibatch_id, microbatch_id,
fsdp_rank, packed_token_offset, checkpoint_replay_id

For every trainer actor pass a in the same global step:
a in P_t = {old_logprob pass, train pass, checkpoint replay passes}

h'_{a,t,z,s,b,c} = h_{a,t,z,s,b,c} * M_t(z,s,b,c) / keep_prob

Clean PPO ratio:
ratio_t(z,s) =
  exp(log pi_theta^M_t(y_{z,s} | x_z)
      - log pi_old^M_t(y_{z,s} | x_z))

Noisy ablation, not the clean baseline:
ratio_bad(z,s) =
  exp(log pi_theta^M_train(y_{z,s} | x_z)
      - log pi_old^M_old(y_{z,s} | x_z)), where M_train != M_old

Micro-Batch Note

The FSDP engine uses dynamic batching with a 36864-token-per-GPU budget, so the exact number of low-level self.module(...) calls depends on sampled response lengths. The stable PPO-level count is still 2 optimizer updates per global step.

Gradient checkpointing can replay internal forward regions during train backward. Those are not extra trainer micro-batches, but they are inside the trainer-side actor execution and should remain masked under the hard rule.

Repo/Paper Check

Point Check
What the paper-derived masking note proves The local note at /Users/shamane/Desktop/major-goal/Activation_Masking_logic.html describes supervised-learning pipeline-boundary activation masking: in-graph random masks, PRF regeneration, forward/backward matched sparsity, and 1/(1-p) rescale for unbiased masked activations. That proof is not an RL/PPO theorem.
What the repo implements ActivationMasker installs forward hooks on logical decoder boundary blocks, builds a deterministic PRF mask keyed by base_seed, layer index, trainer global step, stable sample id, token position, and hidden channel, then applies h * mask or h * mask / keep_prob. The launcher sets rescale on.
RL-specific requirement Because GRPO/PPO forms exp(log_prob - old_log_prob), the supervised masking result is not enough. In RL, every trainer actor forward for the sampled trajectories in a global step must be masked with the same keyed mask for the same token/activation coordinate. This is an additional on-policy consistency condition.
Implementation alignment The repo is mechanically aligned with that RL condition for the paths counted here: the old-log-prob and train paths both stamp the same trainer step and stable per-row ids, and the PRF key does not include forward call, micro-batch id, rank, packed offset, or checkpoint replay id.
Important caveat The current code path is per-token/per-hidden-channel elementwise masking. If a launcher/comment says granularity=channel, that wording should not be read as a separate implemented shared-channel mask here. The mask function in this repo uses token identity plus channel id.
Verdict The implementation is consistent with the paper's masking mechanism, but the RL/on-policy claim is a stricter condition we impose for GRPO. It is not inherited from the supervised-learning proof. For this research run, the correct theoretical stance is: mask every trainer actor forward in the global step, with stable per-token masks across all such passes.
