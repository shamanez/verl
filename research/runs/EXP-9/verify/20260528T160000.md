## Justification

The implementation surface for this issue is small and structurally orthogonal
to the surfaces already verified by EXP-7, EXP-8, EXP-12:

1. **Mask hook eligibility set widening.** `verl/workers/comm_eff/activation_mask.py`
   changes `assert tag == TRAIN_TAG` to `assert tag in MASK_ELIGIBLE_TAGS`,
   where `MASK_ELIGIBLE_TAGS` is gated by `comm_eff.mask.mask_recompute`.
   With `mask_recompute=False` (default) the set is `{TRAIN_TAG}` — strictly
   byte-identical to the current behavior. With `mask_recompute=True` the set
   is `{TRAIN_TAG, "old_logprob"}` — masking extends to the actor's `old_logp`
   recompute, which is the central new behavior of this issue.

2. **`mask_active=True` stamp around `compute_log_prob`.** `verl/workers/
   engine_workers.py::compute_log_prob` enters `_comm_eff_path("old_logprob")`
   already (existing EXP-6 path-tag confinement). The change adds
   `mask_active=True` (gated by `mask_recompute`) inside the context, restored
   on exit. Belt-and-braces atop the `path_tag` assertion.

3. **Config flag and YAML schema.** `Mask.mask_recompute: bool = False` is
   added to `verl/workers/config/comm_eff.py` with `__post_init__` validation,
   and the schema is bound in `verl/trainer/config/actor/dp_actor.yaml` +
   `dp_actor_megatron.yaml`.

4. **Counter surface.** `comm_eff/mask_applications/old_logprob` becomes a
   first-class metric alongside `mask_applications/train`. The existing
   per-path counter infrastructure in `verl/workers/comm_eff/state.py`
   already supports this; the test asserts both keys appear with non-zero
   counts under `mask_recompute=True`.

5. **Regression test.** `tests/workers/comm_eff/test_activation_mask.py`
   gets a new test `test_mask_recompute_path_tag_eligibility` that asserts
   (a) with `mask_recompute=False` the hook still fires only on `TRAIN_TAG`,
   (b) with `mask_recompute=True` the hook fires on `{TRAIN_TAG, "old_logprob"}`,
   (c) the anchor's `path_tag=None` is rejected by the assertion in both modes
   (GUARD 5 preserved), (d) every other tag (`rollout`, `ref_logprob`, `val`,
   `infer`, `ckpt`) is still rejected.

None of these changes touch the anchor backward graph isolation (EXP-12),
the spectral correction math (EXP-7), the GRPO actor-loss reuse (EXP-8),
the FSDP grad-point discovery (EXP-7), or any of the six anchor-semantics
guards. Codex static review of a hook-assertion widening + a config flag
+ a worker-side stamp + a regression test cannot surface new information
beyond what the CPU test suite + runtime greppable counters will catch.

## Acknowledged risk — train-inference mismatch under masked recompute

Masking the `old_logp` recompute changes its log-probs from "the unmasked policy
that emitted the vLLM tokens" to "a masked policy". The PPO importance ratio
`r = exp(log_prob_current_masked − old_log_prob_masked)` will no longer start
at ≈ 1 at PPO inner step 0. This is the documented bet (issue #9 REVISION
comment §4) and is **runtime-falsifiable** via the WandB learning curve
(success criterion 13). If the bet fails, the REVISE branch wires an IS
correction via the existing `rollout_is_weights` channel in
`losses.py:99-100,109,123`; if it succeeds, the comm-efficiency claim is
complete and the M3 100-step run inherits a fully-masked fast circuit.

This is a learning-signal trade, not a correctness defect — it cannot be
caught by codex static review even if codex-bridge were dispatched.
