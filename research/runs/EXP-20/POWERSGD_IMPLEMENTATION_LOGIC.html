Logic-only review note

PowerSGD-Style Activation Compression

A lightweight implementation summary of a low-rank activation codec for tensors passed between model segments. PowerSGD means Power Stochastic Gradient Descent style low-rank projection logic. This version keeps only the algorithmic logic and omits project-specific files, wiring, and experiment details.

1. Core Idea

At a boundary between two model segments, replace the activation matrix M with its projection onto a shared low-rank orthonormal basis Q.

M shape: (N tokens, H hidden)
Q shape: (H hidden, r rank)
Y = M @ Q
M_hat = Y @ Q.T = M @ Q @ Q.T

Only Y, with shape (N, r), needs to cross the boundary. The basis Q is a shared codebook, so it does not need to be sent with every activation.

Symbol key

Symbol Meaning
M The dense activation matrix produced by the previous model segment.
N The number of tokens in the current activation batch.
H The hidden dimension, meaning the number of activation features per token.
r The compression rank, meaning the number of coordinates kept per token.
Q The shared orthonormal basis. Orthonormal means Q.T @ Q = I.
I The identity matrix, which leaves a vector unchanged when multiplied by it.
Y The compressed coordinate matrix that is sent across the boundary.
M_hat The reconstructed low-rank approximation of the dense activation matrix.
.T Matrix transpose, meaning rows and columns are swapped.
A The raw random matrix used before orthonormalizing the initial basis.
V The sketch accumulator used to update the basis after the backward pass.
C_step The activation Gram matrix for one training step. It summarizes feature correlations in the activations.
t The current training step index, so Q_t means the basis used during step t.
k The dense refresh interval, meaning compression is disabled every k steps.
i A data-parallel rank index, meaning one worker among the parallel training workers.
||X|| The size of matrix X using the Frobenius norm, meaning the square root of the sum of squared entries.
Main invariant: if Q.T @ Q = I, then Q @ Q.T is an idempotent projection matrix. The forward pass and backward pass both keep only the same rank-r subspace.

2. Autograd Behavior

The basis Q is treated as a frozen buffer, not a trainable parameter. The activation M remains inside the computation graph. 

frozen_basis = stop_gradient(Q)
Y = M @ frozen_basis
M_hat = Y @ frozen_basis.T

No straight-through estimator is needed. The normal autograd gradient is exactly the projected upstream gradient:

dL/dM = (dL/dM_hat) @ Q @ Q.T

In this expression, L means the training loss, dL/dM means the gradient of the loss with respect to the dense activation matrix, and dL/dM_hat means the upstream gradient with respect to the reconstructed activation.

This means the method optimizes through the compressed activation that the next segment actually receives, rather than pretending the dense activation was used.

3. Basis Initialization

Each boundary gets a deterministic starting basis. The basis is drawn from a seeded Gaussian matrix and orthonormalized in 32-bit floating-point precision. 

seed_boundary = hash(base_seed, boundary_index)
A = random_normal_matrix(H, r, seed=seed_boundary, data_type=float32)
Q = orthonormalize(A)  # 32-bit floating-point QR decomposition with deterministic sign handling
  • Drawing from a deterministic seed lets both sides reproduce the same initial Q.
  • Orthonormalization is done in 32-bit floating-point precision to avoid losing orthogonality.
  • QR decomposition is the matrix factorization used here to turn a raw random matrix into an orthonormal basis.
  • If QR decomposition produces a degenerate or non-finite column, replace it with a deterministic random complement and re-orthonormalize.
  • The basis persists across steps; it is warm-started rather than recreated every forward pass.

4. Basis Update

The basis is not updated by gradient descent. It is refreshed with block power iteration on the activation Gram matrix.

During the training forward

Accumulate a sketch off-graph: 

V += M.T @ (M @ Q)   # equals (M.T @ M) @ Q

Accumulating over micro-batches gives:

V = sum_over_micro_batches M_micro_batch.T @ M_micro_batch @ Q = C_step @ Q

Here M_micro_batch is the activation matrix for one micro-batch. A Gram matrix summarizes feature correlations by multiplying activations by their transpose.

After backward

Orthonormalize the accumulated sketch: 

Q_next = orthonormalize(V)
clear V

This is one block power iteration step:

Q_{t+1} = orthonormalize(C_step @ Q_t)

Repeating this drives Q toward the top rank-r right-singular subspace of the boundary activations, which is the best rank-r reconstruction subspace in Frobenius norm.

Important timing rule: the basis must be read-only during the forward/backward work for a step. Update it only after gradients for that step have been computed.

5. Data-Parallel Consensus

If multiple data-parallel ranks see different samples, each rank accumulates a different local sketch:

V_i = C_i @ Q

The subscript i means one data-parallel rank. C_i is that rank's local activation Gram matrix, and V_i is that rank's local sketch accumulator.

To keep one shared basis, reduce the raw sketches before QR decomposition: 

V_global = all_reduce_sum(V_i)
Q_next = orthonormalize(V_global)

An all-reduce sum means every data-parallel rank contributes its local sketch, all sketches are summed together, and every rank receives the same summed result.

Reducing V is mathematically meaningful because:

sum_i V_i = (sum_i C_i) @ Q
  • Use a sum, not an average; QR decomposition is scale-invariant, so multiplying the whole sketch by a constant does not change the resulting basis.
  • Reduce the raw sketch, not already-orthonormalized per-rank bases.
  • Run collectives in the same boundary order on every rank.
  • If a rank has no data for a boundary, contribute zeros so collective ordering remains identical.

6. Policy-Gradient Timing

For algorithms that compare an old-policy forward with a train-policy forward, both forwards must use the same frozen basis Q_t for the entire global step.

Self-consistency rule: on compressed steps, the old-policy recompute should also use the compression operator Q_t @ Q_t.T. This makes the old-policy denominator and the train-policy numerator evaluate under the same projection. On dense refresh steps, both forwards are dense.
Old-policy recompute On compressed steps, use Q_t and compute M_hat = (M @ Q_t) @ Q_t.T. Do not accumulate the sketch because this forward is under no-gradient mode.
Training forward/backward Use the same Q_t. Accumulate V only from the gradient-bearing training forward.

Updating the basis between these two forwards would change the projection operator and create a spurious importance-ratio shift unrelated to policy parameter changes. Running the old-policy recompute dense while the training forward is compressed is a deliberate ablation setting, not the default self-consistent path.

7. Dense Refresh Cadence

Every k steps, optionally disable compression for the full step. Here k is the clean-cadence value chosen for the run. 

is_clean_step = dense_refresh_cadence > 0
                and step_index is divisible by dense_refresh_cadence

On a clean step:

  • Run both relevant forwards with dense activations.
  • Do not accumulate V.
  • Do not update Q.
  • Let the optimizer see an exact dense gradient periodically.

This acts as a debiasing refresh for optimizer moments and prevents the low-rank projection from being the only gradient path for long stretches.

8. Numerics

  • Store and orthonormalize Q in 32-bit floating-point precision.
  • Cast Q to the activation data type for the projection matrix multiplications if needed.
  • Track Q.T @ Q health; the condition number should stay near 1.
  • Track reconstruction error ||M - M_hat|| / ||M||; this measures whether the learned subspace is useful.
  • If a normalization layer immediately follows the boundary, projection-induced norm shrink is usually absorbed by that normalization. Otherwise, rescaling may need separate validation.

9. Metrics to Report

These are the main measurements to show when reviewing whether the compression logic is behaving correctly. Each metric should be reported per training step, and boundary-specific versions are useful when one boundary behaves differently from the others.

Metric name What it measures How to read it
Basis condition number The largest singular value of Q divided by the smallest singular value of Q. A singular value measures how much a matrix stretches a direction. It should be close to 1. Close to 1 means the basis columns are well orthonormalized. A very large or non-finite value means the basis may have collapsed numerically.
Reconstruction relative error The size of the reconstruction error divided by the size of the original activation: ||M - M_hat|| / ||M||. Lower is better. This is the main quality metric because it tells how much activation information is lost by the rank-r projection.
Cross-rank basis disagreement The relative difference between the basis Q stored on different data-parallel ranks. It should be close to 0. A value near 0 means all ranks are using the same shared codebook. A larger value means the all-reduce or update ordering is not keeping the bases synchronized.
Logical boundary payload The number of compressed coordinates sent per token at each boundary. For this method, the payload is the compression rank r. Smaller values reduce communication but usually increase reconstruction error. This metric states the communication budget being tested.
Basis update count The number of times the algorithm has updated Q using Q_next = orthonormalize(V). It should increase on non-clean steps when an update is due. If it does not increase, the basis is not learning from activations.
Dense refresh count The number of clean steps where compression was disabled and the dense activation path was used. It should match the chosen clean cadence. This confirms the optimizer is periodically receiving an exact dense gradient.
Sketch norm The size of the sketch accumulator V before it is orthonormalized. It should be finite and nonzero on update steps. A zero or non-finite value means the update input is missing or numerically invalid.

10. One-Step Lifecycle

# Training step t, where t is the current step index
Q = Q_t

old policy forward:
    if this is a compressed step, use M_hat = (M @ Q) @ Q.T
    if this is a dense refresh step, use the dense activation M
    do not update Q
    do not accumulate V if the forward is in no-gradient mode

training forward and backward:
    use the same Q_t on compressed steps
    use the dense activation M on dense refresh steps
    if this is a compressed step:
        forward sends Y = M @ Q and reconstructs M_hat = Y @ Q.T
        accumulate V += M.T @ (M @ Q) without recording gradients
        backward sees projected gradient dL/dM = upstream @ Q @ Q.T
    if this is a dense refresh step:
        use the normal dense forward and dense gradient
        do not accumulate V

optimizer step:
    update model parameters

after backward:
    if this is not a clean step and the basis update is due:
        V = all_reduce_sum(V) if using data parallel consensus
        Q_{t+1} = orthonormalize(V)
        clear V
    else:
        Q_{t+1} = Q_t

Knob Meaning
Compression rank Number of coordinates sent per token at each boundary.
Basis update cadence How often to run Q = orthonormalize(V) on non-clean steps.
Dense refresh cadence How often to run a fully dense debiasing step.
Old-policy recompute compression Whether the old-policy recompute uses the same projection as the training forward on compressed steps. Keep this enabled for the self-consistent policy-gradient ratio.

Initialization seed Base seed for deterministic per-boundary initialization.
Orthonormalization precision Precision for orthonormalization; 32-bit floating-point precision is the practical default.

Bottom Line

The method sends r coordinates per token instead of H, keeps the projection differentiable without a straight-through estimator, learns the shared basis with block power iteration rather than gradient descent, freezes that basis across paired policy forwards, and optionally inserts dense refresh steps to control optimization bias.
