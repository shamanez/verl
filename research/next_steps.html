Executive Answer

The anchor circuit is not buggy merely because it does not take multiple optimizer steps. In the current design it is a slow clean measurement loop: it runs a cadence-gated uncompressed backward pass on stale paired data, updates the anchor gradient reference M, and, with anchor.owns_q=true, refreshes the PowerSGD basis Q. The fast circuit is the only circuit that takes live optimizer steps.

Core thesis: the weakness is not that the anchor fails to be a second trainer. The weakness is that the current merger treats a stale anchor gradient as a coordinatewise sign oracle. If RLVR checkpoints really move along a nearly fixed rank-1 direction with a linearly growing coefficient, the anchor should instead become a trajectory clock, basis governor, and residual calibrator.

1. Current interaction

The anchor fires every cadence optimizer ticks, consumes a delay_K-stale replay pair, computes clean G_anchor, updates EMA/reference M, and refreshes/broadcasts Q. The fast network uses that frozen Q during compressed training, then receives a pre-optimizer gradient rewrite.

2. Tick verdict

global_step is the outer rollout/training iteration. anchor_step, spectral_step, and the capture tick are per train_batch optimizer tick. Current 20/20 means 20 optimizer ticks, roughly 10 outer global steps on the observed surface.

3. Research opportunity

Replace coordinatewise sign repair with vector-space correction: rank-1 coefficient estimation, delayed residual feedback, confidence-gated projection, and rank-aware Q allocation. Full sign replacement should become a fallback, not the main idea.

Recommended next move

First, prove the geometry on the local traces at optimizer-tick resolution. Then, before adding new machinery, evaluate the already-present delayed_ef residual pathway plus conservative lookahead. After that, implement a rank-1 line owner inside the anchor path: per tensor direction d_l, coefficient c_l(t), slope a_l, confidence metrics, and a correction rule that preserves the high-confidence line component while damping the orthogonal residual.

Current System: Fast Circuit and Anchor Circuit

There are no literal FastNetwork or AnchorNetwork classes. The names refer to two execution circuits inside the actor training stack.

Rollout + old logprobs

GRPO rollout is ordinary vLLM. The trainer stamps comm_eff_global_step before logprob/actor update.

Anchor refresh first

At cadence, replay a stale paired batch, load stale or projected weights into an isolated clone, disable masks, and run one clean backward.

Anchor outputs

Produce raw G_anchor, update M_anchor, and, in the current baseline, update/broadcast PowerSGD Q.

Fast compressed train

The live actor performs the real training backward with PowerSGD boundary compression using read-only Q.

Merger + AdamW

The spectral merger rewrites target gradients before the single live optimizer step.

Locked surface inspected

The current research baseline uses compression_type=powersgd, powersgd.rank=77, anchor.enabled=true, anchor.owns_q=true, anchor.cadence=20, anchor.delay_K=20, replay_paired_batch=true, spectral.correction_mode=signed_ema, signed_ema_alpha=0.25, and beta_anc=0.50.

Name Current meaning Design implication
Q PowerSGD projection basis. In the current setup it is anchor-owned. The anchor already controls the dominant communication geometry. This is the natural place to inject rank-1 trajectory knowledge.
G_anchor Raw clean gradient from the stale isolated anchor backward. Useful as a calibration measurement, but not automatically a current gradient.
M_anchor / M EMA/reference gradient maintained by the spectral filter. Current signed_ema uses this mostly as a sign field; richer vector information is being discarded.
G_comp Fast compressed gradient before correction. Contains the fresh local batch signal and current-weight information; corrections should preserve this where anchor confidence is low.
G_corr Corrected gradient written back before optimizer step. The right target is not coordinatewise sign agreement; it is better approximation of the full uncompressed update in the optimizer metric.
Important asymmetry: the anchor is allowed to lag. That is the async-realism premise. The goal is not to make the anchor lead by doing hidden local optimizer steps; it is to compensate lag by prediction and by using the anchor measurements in the right subspace.

Training Ticks vs Global Training Steps

The code has two time scales that matter for this research question.

Clock What advances it What it controls Consequence
global_step One outer trainer iteration: rollout, rewards, advantages, actor update, logging/checkpoint cadence. Trainer progress and data-generation epoch. It can span multiple actor optimizer ticks.
optimizer_tick / anchor_step One actor train_batch(...) call, ending in one live optimizer step. Anchor cadence, stale replay indexing, PowerSGD capture keys, and spectral correction timing. Current cadence=20 and delay_K=20 are 20 optimizer ticks.
spectral_step Also advances once per actor train-batch tick. When the gradient merger fires. If spectral cadence equals anchor cadence, correction fires on ticks where the anchor has just refreshed.
Replay snapshot tick In replay mode, one generator snapshot is pushed at the first train-batch tick of each global step. Which stale weights/data the anchor can replay. Realized weight staleness alternates around K and K+1 ticks because snapshots are tied to the first tick of the global step.

Bug or design flaw?

No runtime bug: the anchor not taking multiple optimizer steps is intentional. The anchor pass is documented and tested as a no-optimizer clean backward. It should not silently perform extra AdamW steps, because that would require optimizer state, current rollouts, reward freshness, and an off-policy story. It would also undercut the premise of a slow lagging anchor node serving a fast swarm.

There is a design flaw in usage: the current signed_ema rule treats stale anchor information as if it were a current coordinatewise sign oracle. At high latency, the anchor gradient is not just noisy; it is evaluated at an older point on the RLVR trajectory. The linearity papers suggest this error is predictable, not random. The correction should account for the anchor's time coordinate.

There is documentation drift: some configuration prose calls the cadence units "trainer steps", while the runtime and research traces show optimizer ticks. Future configs and plots should report both: for example, K=20 ticks ~= 10 global steps on the observed 2-tick/global-step surface.

What the RLVR Linearity HTML Adds

The supplied HTML compares two 2026 papers arguing that RLVR fine-tuning trajectories are much more linear than ordinary intuition would suggest.

Paper A: linear dynamics

Reports that individual weights and token log-probabilities are close to linear functions of step during RLVR. The guide attributes this to high-variance outcome-only reward acting like a low-pass filter, producing a stable direction and near-constant speed. It also reports extrapolation and re-grounding speedups.

Paper B: rank-1 trajectories

Reports that cumulative per-tensor deltas are dominated by one singular direction and that the coefficient along that direction grows linearly with very high R^2. RELEX-style extrapolation then predicts later checkpoints from early trajectory structure.

Interpretation for this system

The papers are most useful here not as a promise that every raw gradient is rank-1. In fact, the guide emphasizes that cumulative checkpoint deltas are rank-1 while individual per-step gradients can remain noisy and weakly aligned with the dominant drift. That distinction matters: a communication system should not assume every mini-batch gradient is rank-1. It should assume that the integrated optimizer trajectory has a stable low-dimensional component that can be measured, predicted, and protected.

Local evidence already points in the same direction, cautiously

The local EXP-47/M4 analysis found that damped linear projection outperformed hold-stale in the out-of-sample setting, while naive full linear extrapolation could hurt. The useful operating point was conservative, with a damping coefficient around 0.3, a short best lag around 5, and a strong relationship between higher local linearity and better projection quality. This argues for confidence-gated, damped, per-tensor use of the rank-1 idea rather than an immediate all-or-nothing RELEX transplant.

Mathematical Consequences

For a target tensor or flattened parameter block l, write the observed RLVR trajectory as 

theta_l(t) = theta_l(0) + c_l(t) d_l + r_l(t)
||d_l|| = 1
c_l(t) ~= a_l t + b_l
||r_l(t)|| << |c_l(t)|  on high-confidence tensors

For a matrix tensor, d_l may itself be rank-1, d_l = u_l v_l^T, or a very small low-rank subspace if the top direction drifts. The key prediction is that stale-to-current motion is approximately 

theta_l(t) - theta_l(t-K) ~= a_l K d_l + [r_l(t) - r_l(t-K)]

Animated rank-1 trajectory intuition

theta(0): base checkpoint theta(t): coefficient grows almost linearly
fixed direction d_l moving coefficient c_l(t) small residual r_l(t)

The optimizer-metric caveat

With AdamW or RMSProp-like preconditioning, the line direction observed in checkpoints is a direction of preconditioned parameter updates, not necessarily a direction of raw gradients. If Delta theta_t = -eta_t P_t(g_t), then the rank-1 law constrains P_t(g_t) more directly than g_t. Therefore, the cleanest future correction either acts on the optimizer update after preconditioning or projects raw gradients using an approximate optimizer metric.

Anchor staleness becomes a scalar time-coordinate problem

If the anchor has a snapshot at tick tau = t-K, then under the rank-1 model the missing motion is mostly a_l K d_l. The anchor does not need to simulate K optimizer steps to become useful. It needs an estimate of d_l, a_l, and confidence. That is vastly cheaper and more robust than hidden local training on stale data.

Moving-anchor KL intuition

If the anchor also acts as a reference policy, local KL around the line direction satisfies approximately 

KL(pi_theta(t) || pi_theta(anchor)) ~= 0.5 * (c_t - c_anchor)^2 * d^T F d

A fixed base anchor makes this grow roughly quadratically in time as c_t grows linearly. A rank-1 moving anchor with constant coefficient lag c_anchor(t)=c_t-delta keeps that local KL contribution approximately constant. Even when the current anchor is not used for KL, this is a useful mental model: the right anchor state is a position on the line, not an old full checkpoint treated as timeless truth.

How Rank-1 Linearity Should Change the Anchor's Role

Design principle: the anchor should own the slow, high-fidelity estimate of the trajectory geometry. The fast circuit should own fresh stochastic gradients and optimizer progress. The merger should combine them in a geometry-aware way.

1. Keep the no-optimizer anchor invariant

Do not make the anchor take multiple optimizer steps to "catch up." That turns the anchor into an off-policy second learner and makes it depend on missing optimizer state, reward freshness, rollout state, and mini-batch ordering. Instead, predict the anchor's position along the observed line: 

theta_hat_l(t_target) = theta_l(t_observed) + (c_l(t_target) - c_l(t_observed)) d_l

2. Make the anchor the line-state owner

Each target tensor should have a small state object:

  • d_l: dominant direction or rank-1 factors u_l, v_l.
  • a_l, b_l: slope and intercept for coefficient versus optimizer tick.
  • R2_l, singular gap, residual ratio, and direction drift.
  • Age and freshness of the latest anchor measurement.
  • An eligibility bit: high-confidence tensors use rank correction; low-confidence tensors fall back to delayed residual or no correction.

3. Use anchor-owned Q as a geometry interface

Since the anchor already owns Q, it should reserve part of the PowerSGD basis for the reliable RLVR drift direction and part for the activation/gradient residual. A hybrid basis is more principled than allowing Q to chase only activation energy: 

Q_l = orth([ Q_activation_l, q_drift_l, Q_residual_tail_l ])

This protects the coefficient direction from being compressed away while keeping the remaining rank budget for the orthogonal error that still matters.

4. Project the anchor to the current target before measuring

The existing lookahead machinery already points in this direction. The rank-1 version should select the target tick carefully. In replay mode, the natural target is the current global step's generator snapshot tick, not merely the fire tick, because that is the policy state from which the paired data was produced. The unit for fitting and cadence should remain optimizer ticks.

Using Anchor Feedback Better Than Coordinatewise Sign Correction

The current rule is 

G_correct = alpha * G_noisy
          + (1 - alpha) * abs(G_noisy) * Sign(G_uncompressed)

In practice G_uncompressed is represented by the anchor EMA/reference M. Per coordinate, this keeps the noisy magnitude and interpolates signs: 

G_correct_i = abs(G_noisy_i) *
              [ alpha * Sign(G_noisy_i)
                + (1 - alpha) * Sign(M_i) ]

Animated feedback comparison

Coordinatewise sign repair

Each bar is corrected independently, so tiny noisy coordinates can flip with the same authority as meaningful ones.

Rank-aware residual feedback

Estimate one reliable scalar along the line, then spend correction budget on the trusted residual subspace.

Why this is the wrong default under rank-1 linearity

  • It discards the global low-rank geometry and acts independently on coordinates.
  • It trusts signs of tiny entries where a rank-1 direction has low coordinatewise sign confidence.
  • It preserves noisy magnitudes, which can be upward biased near zero true signal.
  • It ignores anchor age. A stale sign can be systematically wrong because the anchor is behind on a line, not merely noisy.
  • It is not invariant to parameter rotations, while the rank-1 finding is fundamentally a vector or matrix statement.

Replacement family A: delayed residual feedback first

The repo already contains a stronger idea: compare the anchor clean reference to the fast compressed gradient at the same stale paired tick, then add a held or decayed residual to the current fast gradient. 

delta_anchor(t-K) = M_anchor(t-K) - G_comp_ring(t-K)
G_correct(t)      = G_comp(t) + lambda_l(t) * delta_anchor(t-K)

This is better than sign correction because it keeps vector magnitudes, can be gated by age and norm, and has an identity path at lambda=0. It should be the immediate experimental bridge while rank-1 line state is built.

Replacement family B: rank-1 coefficient correction

If the trusted direction for tensor l is d_l, estimate the scalar coefficient of the fresh fast gradient or update: 

beta_hat_l = <G_comp_l, d_l> / ||d_l||^2
G_line_l   = beta_hat_l d_l

A shrinkage form keeps only the reliable line component plus a damped residual: 

P_l        = d_l d_l^T
G_correct = P_l G_comp + lambda_perp_l * (I - P_l) G_comp

In high-confidence tensors lambda_perp_l should be small. In lower-confidence tensors it should move back toward 1. If optimizer-state access is available, apply this to the preconditioned update rather than raw gradient.

Replacement family C: anchor residual in the rank/tail subspace

Use the anchor to measure the compression residual, but only inject the part that lies in trusted subspaces: 

P_trust_l  = projection onto span(d_l, selected Q_tail_l)
delta_l    = M_anchor_l - G_comp_pair_l
G_correct_l = G_comp_l + lambda_l * P_trust_l delta_l

The trust coefficient should be per tensor: 

lambda_l = clip(lambda0
                * f(R2_l, singular_gap_l, age_l, residual_ratio_l,
                    cos(G_comp_l, M_anchor_l)),
                0, lambda_max)

This connects directly to the local finding that high-linearity groups benefit more from projection. It also avoids forcing a global scalar alpha across all tensors.

Replacement family D: exact line plus compressed residual

Treat the dominant line as a control variate: 

G_correct = beta_anchor_hat d
          + C((I - P_d) G_comp + error_t)

Here C is the existing cheap compressor for the orthogonal residual, and error_t is standard error feedback. This is a natural communication-efficient endpoint: transmit or reconstruct the scalar line component accurately, and spend bandwidth only on the residual.

Replacement family E: adaptive sign only as a fallback

If sign correction remains useful operationally, make it confidence-weighted: 

G_correct_i =
  alpha_i G_noisy_i
  + (1 - alpha_i) clipped_mag_i * posterior_sign_i

Set alpha_i from sign reliability: large |d_i|, stable historical sign, fresh anchor, and high tensor R2 lower alpha_i; tiny |d_i|, old anchor, or direction drift raise alpha_i. This avoids injecting structured noise through the many small entries of a rank-1 factor.

Concrete, Prioritized Next-Steps Plan

P0Lock the time semantics before changing algorithms

Produce a small cadence report for every run: global step, optimizer tick, anchor step, spectral step, anchor fire, correction fire, replay data tick, realized weight delay, and ticks-per-global-step. The report should state both tick and global-step equivalents.

Acceptance gate: every plot and config unambiguously says whether K, cadence, and horizons are in optimizer ticks or global steps.

P0Validate rank-1 line structure on local traces

On saved weight trajectories, compute per tensor: 

D_l(t)      = theta_l(t) - theta_l(0)
EV1_l       = sigma_1(D_l)^2 / ||D_l||_F^2
c_l(t)      = <D_l(t), d_l>
R2_l        = R^2(c_l(t), t)
residual_l  = ||D_l(t) - c_l(t)d_l|| / ||D_l(t)||

Run this both per optimizer tick and per deduplicated global step. Compare the rank-1 fit against existing two-point linear lookahead, OOS damped linear projection, and hold-stale. Do not assume the paper's R2 > 0.98 result transfers to every tensor or to Qwen 1.5B GRPO under compression.

Acceptance gate: identify a whitelist of tensor families where rank-1 confidence is high and a blacklist where it is weak, especially LayerNorm, embeddings, and heads.

P1Run the lowest-risk algorithmic bridge: delayed-EF plus damped lookahead

Before implementing a new rank-1 module, compare current signed_ema against the existing delayed_ef path. Use conservative lambda values, age decay, norm clipping, and adaptive per-tensor gating. Combine with existing lookahead only at the OOS-damped strengths suggested by local analysis, not full naive extrapolation.

Acceptance gate: at high latency, delayed_ef must improve cosine or MSE to dense captured gradients and avoid k-collapse relative to signed_ema. If it cannot beat sign correction, the anchor measurements themselves are not reliable enough yet.

P1Build a rank-1 line-state sidecar

Add an experimental state object that is updated only on anchor fires or checkpoint dumps. It should estimate d_l, c_l(t), a_l, R2_l, singular gap, residual ratio, and drift. The initial version can be offline or research-only. It should expose a pure function: 

predict(theta_snapshot, source_tick, target_tick, tensor_id)
  -> theta_hat_tensor, confidence

Acceptance gate: prediction must beat hold-stale out of sample under the same no-peek constraints as EXP-47, and confidence must correlate with improvement.

P1Use projected anchors, not catch-up anchors

Feed theta_hat into the existing isolated anchor clone instead of raw theta[t-K]. The anchor still runs exactly one clean backward and no optimizer step. This tests the thesis directly: staleness should be handled by line-coordinate prediction, not by local catch-up training.

Acceptance gate: projected-anchor gradients should align better with dense current gradients than stale-anchor gradients on paired captures, without increasing instability.

P1Replace sign repair with rank-aware residual correction

Implement the per-tensor rule: 

delta_l       = M_projected_l - G_comp_pair_l
P_trust_l     = span(d_l, selected Q_tail_l)
lambda_l      = confidence_gate(R2_l, gap_l, age_l, residual_ratio_l)
G_correct_l   = G_comp_l + lambda_l * P_trust_l(delta_l)

Keep an identity path for low confidence. This should be compared to signed_ema, delayed_ef, and no correction.

P2Make Q trajectory-aware

Split the rank budget. Reserve a small number of columns for the high-confidence rank-1 drift direction and use the rest for activation/residual sketching. The expected benefit is not only better compression quality but also better stability: the most predictable part of the RLVR update should not be left to chance.

P2Explore scalar-only and low-rank training limits

Once the line-state estimator is trustworthy, run ablations that constrain the update to theta_0 + c_t d, rank-1 LoRA, rank-4 LoRA, and projected full updates. These are not immediate production candidates; they are scientific probes that tell us how much of the RLVR improvement is captured by the single coefficient versus the residual.

Algorithm Sketch

On each anchor fire at optimizer tick t:
  1. Fetch paired replay batch and source snapshot tau = t - K.
  2. Update or read line state for each target tensor:
       d_l, a_l, b_l, R2_l, singular_gap_l, residual_ratio_l.
  3. Choose target tick t_target:
       replay mode: current generator snapshot tick;
       otherwise: current optimizer tick.
  4. Build projected anchor weights:
       theta_hat_l = theta_l(tau) + (a_l * (t_target - tau)) d_l
       only for tensors passing confidence gates.
  5. Run one clean anchor backward at theta_hat. No optimizer step.
  6. Update M_anchor and delayed residual estimates.
  7. Update Q with a hybrid basis:
       Q_l = orth([Q_activation_l, q_drift_l, Q_residual_l]).

On each fast optimizer tick:
  1. Run fast compressed backward using read-only Q.
  2. If correction fires:
       compute per-tensor confidence lambda_l;
       apply delayed/rank-aware residual correction;
       leave low-confidence tensors unchanged.
  3. Run the single live optimizer step.

Success Metrics and Kill Criteria

Category Measure Pass condition
Geometry R2_l, singular gap, EV1_l, residual ratio, direction drift. High-confidence tensors have stable direction and line coefficient; low-confidence tensors are gated out.
Gradient/update quality Cosine to dense gradient/update, MSE, norm ratio, sign flip precision/recall. Correction improves over G_comp and current signed_ema on dense capture windows.
Training behavior Verifier pass rate, reward, KL, entropy, response length, NaNs, collapse signatures. No k-collapse at the high-latency surface; no reward-hacking acceleration via entropy collapse.
Systems cost Wall time, anchor backward count, Q broadcast bytes, CPU snapshot pressure, memory. Additional line-state logic remains cheaper than increasing anchor cadence or doing anchor catch-up optimization.
Async realism Whether future information leaks into line prediction or replay pairing. No-peek discipline preserved. Anchor may predict from past line state, not read future checkpoints.
Kill criterion: if the estimated line direction is unstable on local compressed GRPO traces, stop treating rank-1 as a universal control path. Fall back to delayed residual feedback and use rank-1 only for the tensor families where the evidence is strong.
