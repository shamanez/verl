EXP-29: The Trajectory Fix — Make the Anchor Grade Its Own Homework

Every result up to this point rested on a quiet assumption that turned out to be wrong. The anchor circuit's whole job is to compute a clean, trustworthy gradient \(M\) from a stale snapshot of the weights — but it was computing that gradient on the wrong data. It graded the current policy's answers using old weights, which is neither the old policy's gradient nor the new one's. EXP-29 (issue #29, “Correct the anchor gradients trap utilisation”, operator-directed after a code review) fixes this: the anchor now replays the exact trajectories its stale weights actually generated. No training-curve headline — this is an infrastructure correctness fix — but it is the fix that made the later SOTA legitimate.

What the anchor is supposed to compute

Recall the two-circuit design. The fast compressed circuit runs every step; the anchor circuit fires every few ticks, loading a delay_K = 5-tick-stale snapshot of the weights into a clean, no-compression clone and running one full forward/backward to produce the true gradient average \(M\). That \(M\) is the program's reference signal — the merger folds it into the noisy compressed gradient, and it drives the projection basis \(Q\). If \(M\) is contaminated, everything downstream inherits the contamination.

The anchor uses a deliberately clean loss (anchor_pg_loss, verl/workers/comm_eff/anchor.py): a plain REINFORCE policy gradient with the importance ratio held at \(1\) (no PPO clipping, old_log_probs deliberately ignored), so its gradient is exactly

$$ G_{\text{anchor}} \;=\; \nabla_\theta\big[\!-\!A \cdot \log\pi_\theta\big]\Big|_{\theta = \theta_{t-K}} \;=\; -\,A\cdot\nabla_\theta\log\pi_{\theta_{t-K}}. $$

This is the textbook “clean step's gradient, evaluated at the stale weights.” The advantages \(A\) and the response tokens are read straight off the batch. And there is the trap: which batch?

The bug: the anchor graded the current policy's trajectories

On the training path, GRPO is on-policy — for each step \(t\), vLLM generates rollouts using the current weights (\(\theta_{t-1}\)), and the advantages \(A\) are computed from those rollouts' rewards. The old anchor refresh loaded the stale weights \(\theta_{t-K}\) into the clone but then forwarded anchor_data = data.copy() — the current tick's batch (transformer_impl.py). So it computed

$$ G_{\text{anchor}}^{\text{(old)}} \;=\; -\,A_{\text{current}}\cdot\nabla_\theta\log\pi_{\theta}\Big|_{\theta=\theta_{t-K}}, $$

with no importance correction between the policy that generated the data (\(\pi_{\text{current}}\)) and the weights doing the scoring (\(\theta_{t-K}\)). This object is neither the stale policy's true gradient (that would need the stale policy's own trajectories) nor the current policy's (that would need the current weights). It is a stale-weights × current-batch confound — a mismatch baked into \(M\)'s content across all of EXP-25, EXP-26, and EXP-27.

The analogy. Picture the careful clerk again, the one who keeps the only fully-correct copy of the ledger. The clerk is meant to redo this morning's transactions using the rules as they stood a week ago, to measure how much the rules have drifted. Instead, the clerk was redoing today's brand-new transactions with last week's rulebook — an answer to a question nobody asked. The drift measurement is contaminated by the fact that the transactions themselves are not the ones last week's rules would have produced.

This was a deliberate original design choice, not a coding slip — “the clean step's gradient at the stale weights” was taken to mean “clean loss, stale weights, whatever batch is in hand.” But for the decentralized-pipeline target the right object is unambiguous: a slow, out-of-date worker computes gradients on the trajectories it itself generated from its own weights. The confound had to go before any claim about how to use \(M\) could be trusted.

The fix: on-policy replay

The correction (anchor.replay_paired_batch = true) is conceptually simple and costs no extra generation. A fire-aware ring buffer retains recent mini-batches — the tokens and their advantages — each tagged with the weights that produced it; when the anchor fires, it replays the paired batch instead of the current one (anchor_data = _replay_batch.copy(), transformer_impl.py):

$$ G_{\text{anchor}}^{\text{(fixed)}} \;=\; -\,A_{t-K}\cdot\nabla_\theta\log\pi_{\theta}\Big|_{\theta=\theta_{t-K}} \qquad\text{on the batch } \theta_{t-K}\text{ generated.} $$

Now the weights and the trajectories match: a self-consistent on-policy gradient of the stale snapshot. The alignment is exact, not approximate — the weight snapshot taken at the first training tick of a global step is precisely the snapshot vLLM used to generate that step's rollouts, so storing one snapshot per global step plus the per-tick batches yields exact (batch, generator-weights) pairs (warmup included). Data staleness is exactly \(K\) ticks; the weights are always the batch's true generator (realized weight staleness \(K\) or \(K{+}1\) on the two-ticks-per-step substrate, logged and hard-asserted never fresher than \(K\)).

A companion knob, anchor.snapshot_device = cpu, moves the delay_K + 1 full weight snapshots (~18.6 GB if kept on the GPU) into CPU RAM, loaded to the device only inside the refresh. The batches were already CPU-resident, so the new ring costs essentially zero extra GPU memory — an explicit operator requirement (the fixed substrate must not grow its HBM footprint). Both knobs default OFF (replay_paired_batch = false, snapshot_device = gpu): with the fix disabled, not a single existing line changes and the run is byte-identical to before.

How we know it is correct

Because this touches the gradient that everything else trusts, EXP-29 shipped behind a wall of hard correctness gates rather than a validation number.

GateWhat it checksResult
Off-path parity With the fix off, no ring is constructed, no new collective or RNG runs — every existing line executes unchanged (CPU-tested: no replay ring is even built). byte-identical
Stale-weight value canary On every fire, the fp32 norm + sum of canary weight matrices recorded when the snapshot was pushed must equal the values recomputed off the clone after it loads — bitwise (the bf16→CPU→device round-trip is byte-preserving). bitwise match every fire
Exact pairing Every post-warmup fire asserts used_tick == step − delay_K and batch_gs == snapshot_gs — the replayed batch is provably the \(t{-}K\) batch and its true generator snapshot. asserted every fire
Relevance probe The decisive value-level check. Each replayed batch stores the log-probs it was generated with; the anchor's forward at the loaded snapshot re-scores the same tokens. If the loaded weights are truly the batch's generator, the masked \(\lvert\log\pi_{\text{loaded}} - \log\pi_{\text{stored}}\rvert\) sits at the engine-noise floor and stays flat across fires; a broken pairing would drift and grow with each policy update. flat, at the noise floor (~0.01 nats)
Zero GPU-memory growth Peak allocated memory must stay below the prior healthy-phase baseline — snapshots and replay batches live in CPU RAM. max_mem 30.77 GB, below baseline

All hard gates passed; the verdict is an infrastructure PASS (there is no parity bar on a correctness fix — replay deliberately changes the science, so a val gate would be meaningless; the “not broken” check was val@25 ≥ 0.60). The change merged as PR #16 on the fork and is now a permanent, default-available part of the substrate.

Why it mattered — and, honestly, what it did not fix

The enabling consequence. With a self-consistent anchor, the residual \(\delta = G_{\text{anchor}}^{\text{rep}} - G_{\text{comp}}\), measured at identical batch and weights, becomes a clean measurement of one thing only: the error the codec introduced. The relevance probe's noise floor (~0.01 nats) is the same band EXP-30 later used to certify that \(\delta\) is codec error and not an objective/data mismatch. That clean \(\delta\) is exactly the quantity the SOTA merger (EXP-30's delayed_ef, λ=1) re-injects — so on-policy replay is the precondition that made the next experiment's parity result legitimate rather than confounded.
The honest non-result. Making \(M\) valid did not rescue the old sign / blend idea. When EXP-30 measured it, the valid generator-consistent gradient was just as orthogonal to the live compressed gradient as the old confounded \(M\) had been (\(\cos \approx 0\) either way). So the EXP-25 “sign agreement is a coin-flip” finding was genuinely structural, not an artifact of the trajectory confound — fixing the data did not open up the blend geometry (which is why EXP-30's blend gate closed without a training run). The trajectory fix and the sign coin-flip are two independent facts: EXP-29 removed a real confound and unlocked the residual route to SOTA, but it did not un-falsify the sign-replacement route. Both readings stand together.
