## Hypothesis

There **exists** a gradient correction — driven by the **stale** (`delay_K=5`) anchor's true-gradient reference, applied as a **force** on the masked gradient every masked step (anchor `cadence=5`, `clean_cadence` **OFF**) — under which the masked+correction **per-step GRPO training signal** (reward `critic/score/mean` + policy loss `actor/pg_loss`) **tracks the dense run's training signal across the whole ≤50-step trajectory**. Concretely, for at least one candidate, all of the following hold over GSM8K steps 1..50 at mask `p=0.9` (rescale ON, recompute ON), anchor `cadence=5`, `delay_K=5`, `clean_cadence=0`:

- **mean per-step `|reward_masked(t) − reward_dense(t)|` ≤ 0.05** over steps 1..50, **AND**
- **final-step gap `|reward_masked(50) − reward_dense(50)|` ≤ 0.05**, **AND**
- the masked+correction reward stays at the **dense level** (no collapse to the pure-masked ~0.13 floor) and its **within-window slope sign matches dense** (moves with dense, not flat/diverging), **AND**
- the policy-loss / `pg_loss` curve tracks dense over the same window (same sign of motion, no blow-up), with `actor/grad_norm` finite throughout.

**Falsified (for a given candidate)** if the mean reward gap stays > 0.05, OR the masked+correction reward collapses toward the pure-masked ~0.13 floor, OR the curves diverge in sign/scale, OR `grad_norm` goes non-finite. **Falsification of one candidate is expected and is data** — the agent theorizes WHY, refines or proposes the next candidate, and loops. The *issue* is resolved when the FIRST candidate clears the bar. No validation / lm_eval this cycle — the training-signal curve match is the **sole** PASS criterion (validation is deferred to a confirm-on-a-longer-run follow-up after a match is found).

This plan bakes in the **"observe → theorize → propose new → test"** loop as the agent's core working mode. Two things the agent MUST do explicitly:

- **(i) Explore directions DERIVED FROM THE CURRENT SPECTRAL CORRECTION.** Start from what the as-implemented `SpectralFilter` does — a **linear reweighting of `G_mask`** inside the stale-anchor SVD subspace, proven inert by orthogonality (GSM8K 0.080, pearson ~0.004) — and **derive concrete new candidates from it**, e.g.: the minimal change that turns its *reweighting* into *additive injection* of the missing component; reusing the same anchor SVD basis but projecting the stale `g_true` onto the **complement of `span(G_mask)`** and adding it; replacing the linear filter with an explicit `b`-estimator term fed by the stale anchor. Use the current spectral as the **departure point**, then go beyond it. Its ≤50-step curve is cached as the floor (sequence step 1b).
- **(ii) Propose NEW methods FROM THE RESULTS.** Each iteration, after comparing curves, the agent must **theorize WHY** the candidate did/didn't track dense (tie it to `b`, orthogonality, staleness) and **propose the next method from that evidence** — a results-driven hypothesis, not just the next item off a static list.

**Before running any candidate**, the agent MUST **enumerate ALL candidate corrections theoretically** — a complete written list (including the spectral-derived ones from (i) and any derived from first principles), each entry stating:
1. its **mechanism** — precisely what it computes from the stale anchor signal and how it modifies the optimizer update;
2. the **rationale** — why it should make the masked curve track dense, tied to `g_mask = g_true + b + ξ` (how does it supply/cancel `b`?);
3. **how it respects the three HARD CONSTRAINTS** — (a) no direct full-gradient optimizer step, (b) it functions under `delay_K=5` staleness, (c) it SUPPLIES the missing component rather than reweighting `G_mask` in a subspace;
4. its **predicted training-signal-match behavior** — where on the 50-step curve it should help / where it might fail.

This theoretical enumeration is a **machine-checkable deliverable** (see Success criteria) and a precondition to the first candidate run.

## HARD CONSTRAINTS (verbatim — non-negotiable; every candidate run obeys all three)

1. **NO periodic full-gradient updates.** The periodic clean step (`clean_cadence` — directly applying a fresh dense gradient every K steps) was used ONLY as an existence proof that the recoverable signal is there. It is **NOT** the method. `clean_cadence` stays **OFF** (`COMM_EFF_CLEAN_CADENCE=0`) and must not be reintroduced. The only full-fidelity passes allowed are the anchor's **STALE** reference passes that FEED the correction — never a fresh full gradient applied directly as the optimizer update.
2. **STALENESS IS STRICTLY MANDATORY.** `delay_K = 5`, and it must **NEVER be 0**. The anchor's reference signal must always be stale, because this targets a realistic decentralized / pipeline-parallel system where a full gradient can NEVER arrive fresh — it always lands ~K steps old (the unmasked pass is ~20× a masked step over a slow link). A correction that only works with a fresh (`delay_K=0`) anchor is **INVALID** — it would not survive deployment. Every candidate run pins `COMM_EFF_ANCHOR_DELAY_K=5`. **Never run delay_K=0; never run delay_K=20 here** (20 is the launcher default — it MUST be overridden).
3. **The correction must SUPPLY the component the masked gradient lacks and work UNDER staleness** — not merely reweight the masked gradient in a subspace. (This is exactly why the as-implemented spectral filter was inert: no linear reweighting of a near-orthogonal vector synthesizes the missing `b`-correction.)

### Candidate corrections to explore (OPEN — starting points, NOT a prescription; the agent is expected to go BEYOND this list)
All must respect Constraint 3 (supply what `G_mask` lacks, don't merely reweight it) and work under `delay_K=5`:
- **Direct bias removal** — estimate `b` from the stale anchor's true-gradient signal and apply it as an additive force on the masked gradient, with a **staleness-aware decay** (the anchor is 5 steps old; weight it accordingly).
- **Boundary-activation correction** — act on the **boundary activations** (cheap, local) rather than the full parameter gradient, to inject the missing component where the mask removed it.
- **Additive subspace methods** — methods that **ADD a missing component** (e.g. project the stale `g_true` onto the complement of `span(G_mask)` and inject it) rather than reweighting an existing one.
- **Stale-aggregation variants** — different aggregations / decays of the anchor signal across its 5-step staleness (EMA, extrapolation, momentum-debiasing).

*Where the code is:* the anchor circuit is plumbed (`verl/workers/comm_eff/anchor.py`: a `delay_K`-stale isolated clone producing the raw unmasked gradient; today it only feeds the EMA, never the optimizer). **Wiring its signal into the actual update is the load-bearing code change.**

## Match metric — what to measure (no validation this cycle)

Per-step training-signal curves, masked+correction overlaid on dense (cached), step axis 1..50:
1. **Reward** — `critic/score/mean` per step. Compute: (i) mean per-step `|Δreward|`, (ii) final-step `|Δreward|`, (iii) within-window slope (sign + magnitude vs dense).
2. **Policy loss** — `actor/pg_loss` (and total policy loss) per step: same-sign motion, no blow-up, tracks dense.
3. **Stability companions** (sanity, not the criterion) — `actor/grad_norm` finite throughout; `pg_clipfrac` bounded; mask confined to actor-train; `clean_cadence` fired **0** times; anchor fired at cadence 5 with `delay_K=5` (counters consistent).
