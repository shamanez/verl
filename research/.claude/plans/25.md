## Hypothesis

On the fixed GSM8K surface (Qwen2.5-1.5B-Instruct, vanilla GRPO no-KL/no-entropy,
lr 1e-6, train_batch 128, ppo_mini 64, n=8, max_response 16384; 50 steps then 100,
validation every 25, anchor refresh every 5 steps from stale weights, **no**
periodic clean step), the anchor-default substrate — full-coverage stale-`M` (R1)
+ anchor-owned `Q` (R2) + the signed_ema merger
`G_correct = α·G_noisy + (1−α)·|G_noisy|·sign(M)` applied every fast step (R3),
α swept — recovers the comm-efficiency gap that EXP-23's `inject`/`blend` could
NOT. **Numeric thresholds:** for the best α, `val@50 >= 0.7315` (within ~1 pt of
A0 fresh-clean 0.7415) AND `val@50 >= floor + 0.05` where the floor = the
no-anchor PowerSGD r=77 run = 0.6914 (i.e. `>= 0.7414`); meanwhile the
all-flags-OFF path stays byte-identical to EXP-20 PowerSGD r=77
(`q_cross_rank_max_rel_dev = 0`, `reconstruction_rel_error` within 1e-3 of 0.024).
**FALSIFIED** if best-α `val@50 <= floor + 0.02 = 0.7114` (no better than
no-refresh PowerSGD).

**R2 (id 1) — MOVE Q OWNERSHIP TO THE ANCHOR. This is a MUST and it is the main
structural inversion of #25 — build it ONLY after R1 is verified-correct, because
R2 harvests Q from the SAME anchor stale-forward pass that R1 establishes (Q comes
from that forward's activations; M from its backward).**

> **Q IS NOT STATIC.** It is initialized ONCE (the deterministic `init_basis`
> cold-start cache) and from then on UPDATED time-to-time — every anchor refresh.
> The update METHOD is taken verbatim from the fast circuit (`V += Aᵀ(AQ)` →
> `Q ← orth(V)`) and simply RUN ON THE SLOW circuit using ITS activations. So the
> change vs today is *only* WHERE the update happens (fast → slow) and WHOSE
> activations feed it (the slow net's stale-weight forward) — the update itself
> keeps happening, on cadence, forever.

State it three ways so it cannot be misread:

1. **The fast network MUST NOT update Q — ever. (Hard requirement.)** Today the
   FAST net is the SOLE Q-updater (`maybe_update_basis`, sole call site
   `engine_workers.py:~941-943`, in the `finally` of `train_mini_batch`). From #25
   onward that call is GATED OFF in anchor-owns-Q mode and the fast-side activation
   sketch is never folded into Q. The fast net only ever USES Q (read-only:
   `Y=M@Q`, `M_hat=Y@Qᵀ`) and holds it FIXED between refreshes. This is not a
   nice-to-have — if the fast net keeps updating Q locally while the anchor also
   distributes Q, the two Qs diverge and either `verify_basis_agreement_across_ranks`
   RAISES or the two sides of a boundary silently desync, breaking the projector
   identity.
2. **Q MUST still be updated — but in the ANCHOR, from the anchor's FORWARD
   ACTIVATIONS (NOT from `M`).** "Fast net doesn't update Q" does NOT mean Q is
   frozen. Q is actively recomputed EVERY anchor refresh, on the anchor side, from
   the SLOW net's uncompressed forward-pass boundary ACTIVATIONS at the θ_{t−K}
   stale weights — the SAME activation second-moment the fast PowerSGD Q-update
   uses today (`V += Aᵀ(AQ)` → `Q ← orth(V)`), just relocated to the slow circuit.
   It is NOT derived from the gradient EMA `M` (see (i) below — the fast Q-update
   uses NO gradients, and `M` is model-sized per-weight, the wrong object/shape for
   an `(H,r)` activation basis). The anchor is the SOLE writer of Q; the fast net
   is a pure consumer. **One anchor pass yields BOTH: forward activations → `Q`,
   backward grad → `M`.**
3. **`init_basis` (deterministic seed) is retained ONLY as a cold-start cache** so
   a fast net has *some* Q before the first anchor broadcast lands, and it is NEVER
   updated live thereafter.

**Broadcast + receipt — be EXTRA careful here; this is the second-most-likely silent
bug after `M` itself.** It is not enough to "disable fast updates and broadcast from
the anchor" — you must PROVE the broadcast actually reaches every fast/DP rank, for
BOTH `Q` AND `M`:
- The anchor (the owning rank) `dist.broadcast`s the refreshed `M` and `Q` over the
  actor process group, in a FIXED boundary order, on the SAME refresh path for both.
- Every fast/DP rank `copy_`s the received `M`/`Q` into its held copy. **Verify the
  receipt positively** (see the `(R2) the broadcast LANDS` invariant): after the
  broadcast, the fast-side held `Q`/`M` is bit-equal to the source AND has CHANGED
  from its pre-broadcast value when the source changed. A dropped broadcast, a wrong
  process group, a `copy_` into the wrong tensor, or a dtype/shape mismatch that
  silently no-ops would leave the fast net running on a STALE or cold-start `Q`/`M`
  forever — the run would not crash, it would just quietly train on the wrong basis.
  That is exactly the failure this positive check exists to catch.
- Emit a `[comm_eff][bcast]` log line per refresh (source checksum, each rank's
  received checksum, `changed=true/false`) for both `Q` and `M`, so the receipt is
  greppable on a hands-off run. The cross-rank consensus guard MUST be preserved.

**Q-operator decision — PINNED in this plan (it MUST NOT float into the
implementation).** The issue raised two sub-decisions; resolve them as follows for
the id-1 build:
- **(i) Q INPUT = the anchor (slow) net's forward-pass boundary ACTIVATIONS at the
  θ_{t−K} stale weights — NOT the gradient `M`.** (This corrects an earlier
  mis-pin that said "Q from M".) VERIFIED against the code: the fast Q-update uses
  NO gradients — it builds Q purely from the forward activation second-moment
  (`A = h.reshape(-1,H)` at `powersgd_activation.py:332`; sketch `V += Aᵀ(AQ)` at
  `:374`; `Q ← orthonormalize(V)` at `:512`; the only `grad`-named symbol,
  `grad_enabled` at `:316`, is just a forward-pass SELECTOR, never a gradient
  VALUE). So moving Q-ownership to the slow net = run that SAME activation sketch on
  the slow net's uncompressed forward (already executed for the anchor backward)
  and orthonormalize. The gradient EMA `M` is model-sized per-weight — the WRONG
  object for an `(H,r)` per-boundary activation basis (Codex #4); `M` feeds ONLY the
  merger's `sign(M)`, never Q. This is also exactly what the SL `slow_basis` winner
  does (Q from the slow circuit's activations, not the gradient).
- **(ii) Q ALGORITHM = the SAME `orth(V)` block-power-iteration the fast PowerSGD
  already runs, just on the slow net's activations** — pinned for the FIRST build
  because it reuses the existing, validated codec math verbatim (lowest integration
  risk; only the activation SOURCE moves fast→slow, the math is unchanged). The SL
  `slow_basis` estimator (EMA of activation covariance `AᵀA` → `eigh` top-r) is the
  FIRST REVISE ablation — SAME input (slow-net activations), different estimator.
  Either way the input is activations, never the gradient `M`.
- **(iii) Transfer + cadence (CONCRETE):** once per anchor refresh (every
  `anchor.cadence=5` steps) the anchor computes fresh `M` and `Q` and BROADCASTS
  both to all fast/DP ranks (`dist.broadcast` from the anchor-owning rank over the
  actor process group, fixed boundary order, same transfer path for `M` and `Q`)
  ⇒ every boundary on every rank holds ONE identical `(M, Q)`. Fast nets hold
  `(M, Q)` FIXED between refreshes (read-only during the step, like today's
  frozen-Q rule).

**R3 (id 1) — the new merger.** Implement
`G_correct = α·G_noisy + (1−α)·|G_noisy|·sign(M)` as a NEW additive
`correction_mode=signed_ema` in `spectral_filter.py`, **flag-gated, OFF by
default**, distinct from `inject`/`blend` (failed EXP-23) and `reweight` (inert
EXP-21). **Carry the SL semantics EXACTLY:** `sign(...)` = `sign(M_anc)` (sign of
the β-EMA of the K-STALE anchor gradient), magnitude `|G_noisy|` = the FAST
compressed grad. Do NOT promise "sign of the fresh full gradient." α is a SWEPT
hyperparameter (id 2) — α=0 is SFT-validated but RL may differ; at α=0 the rule
reduces to `|G_noisy|·sign(M_anc)`.
- **COLD-M FALLBACK IS MANDATORY (silent grad-zeroing trap — most dangerous bug in
  R3).** Before applying the formula, replicate the existing cold-anchor guard from
  `blend_matrix` (`spectral_filter.py:520`: `if anc_norm <= eps or gm_norm <= eps:
  return g_mask`): if `M[name]` is unwarmed/zero, **return `G_noisy` unchanged**
  (i.e. behave as α=1 for that matrix). Otherwise `sign(0)=0` and at α=0 the term
  `(1−α)·|G_noisy|·sign(M) = 0` ⇒ `G_correct = α·G_noisy = 0` — the gradient is
  SILENTLY ZEROED. This bites on the **first `delay_K` steps** (M not yet refreshed)
  and on **any matrix M fails to cover**. A naive transcription of the formula
  WITHOUT this guard passes every other invariant and quietly kills learning. Emit
  `merger_coldM_fallbacks=N` per step so the probe can prove the fallback fired
  (step 1) and then stopped (after warm-up).
- **`seed_anchor_cache` MUST be `false` for #25** (it defaults `true`,
  `comm_eff.py:215`). With it `true`, `M` is pre-seeded with a FAKE deterministic
  PSD basis, so `sign(M)` would be the sign of garbage until the live anchor
  overwrites it (and it breaks the R1 scale-check). The live anchor circuit owns
  `M` end-to-end; there is no fake seed. (When the spectral path is removed,
  `seed_anchor_cache` goes with it — but until then it must be explicitly OFF.)
- **NB the SAME `max_targets` caps the MERGER too** (`apply_spectral_correction_to_params:591`
  `if corrected >= max_targets: break`), not just the anchor extraction. So
  `max_targets=-1` is required for the merger to correct all 196 — a residual cap
  would make the merger silently skip matrices even when `M` covers them. (One knob,
  both paths; the set-equality invariant assumes both uncapped.)
