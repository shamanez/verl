## Hypothesis

On the fixed GSM8K surface (Qwen2.5-1.5B-Instruct, vanilla GRPO no-KL/no-entropy,
lr 1e-6, train_batch 128, ppo_mini 64, n=8, max_response 16384; 50 steps then 100,
validation every 25, anchor refresh every 5 steps from stale weights, **no**
periodic clean step), the anchor-default substrate — full-coverage stale-`M` (R1)
+ anchor-owned `Q` (R2) + the signed_ema merger
`G_correct = α·G_noisy + (1−α)·|G_noisy|·sign(M)` applied every fast step (R3),
α swept — recovers the comm-efficiency gap that EXP-23's `inject`/`blend` could
NOT. **Numeric thresholds:** for the best α, `val@50 >= 0.7315` (within ~1 pt of
A0 fresh-clean 0.7415) AND `val@50 >= floor + 0.05` where the floor = the
no-anchor PowerSGD r=77 run = 0.6914 (i.e. `>= 0.7414`); meanwhile the
all-flags-OFF path stays byte-identical to EXP-20 PowerSGD r=77
(`q_cross_rank_max_rel_dev = 0`, `reconstruction_rel_error` within 1e-3 of 0.024).
**FALSIFIED** if best-α `val@50 <= floor + 0.02 = 0.7114` (no better than
no-refresh PowerSGD).

### Vast.ai utilization discipline (HARD RULE — honored)

- **One instance for the whole sequence.** id 0 → id 1 → the 3 α arms all chain
  back-to-back on the SAME warm box (shared docker / verl checkout / dataset
  cache / vLLM init). Tearing down + reprovisioning between sequential runs is
  forbidden.
- **No parallelism within the box.** At train_batch 128 × n=8 × 16K response on a
  4–8 GPU box the α arms cannot be partitioned to run concurrently — `fanout_max:
  1`, they run sequentially.
- **Tear down the instant the science is captured.** When the last α arm (or the
  winner's 100-step extend) writes `done.flag` and metrics rsync to the laptop,
  the runner / Stop hook tears down on the next tick. No "leave it up for the
  analyst." The analyst reads metrics from the laptop.
- **No known-idle phase is designed in** — the GPU-stall watchdog's default
  thresholds apply (no loosening requested). The anchor's second backward keeps
  GPUs busy every step.
