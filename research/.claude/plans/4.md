## Hypothesis

Adding the `comm_eff` config group and a disabled-by-default integration hook into the verl GRPO actor path is a **bit-for-bit no-op when disabled**. Concretely, with the scaffolding merged: (1) running the baseline launcher with **no `comm_eff` overrides** (config default `comm_eff.enabled=false`) and again with explicit `comm_eff.enabled=false`, a two-step GRPO smoke on Qwen2.5-1.5B-Instruct / GSM8K reaches `global_step=2`, executes ≥2 (expected **4**) actor optimizer substeps, keeps `actor/grad_norm` **finite and < 5** on every substep, shows **no NaN/Inf** in any loss/grad/reward/log-prob field, and changes **≥1 actor parameter** between step 0 and step 2; (2) the instrumented comm_eff operation counters are **all exactly 0** when disabled — `comm_eff/mask_applications == 0`, `comm_eff/anchor_backwards == 0`, `comm_eff/spectral_corrections == 0` across both steps (the disabled object must not register hooks, allocate spectral state, or touch the gradient); (3) the deterministic post-rollout actor scalars (`actor/pg_loss`, `actor/kl`, `actor/entropy`) computed with `comm_eff.enabled=false` match a back-to-back unmodified-launcher smoke at the **same seed and same rollout RNG** within **relative tolerance 1e-4**. **Falsified if** any comm_eff counter is nonzero when disabled, any disabled-path scalar diverges > 1e-4 from the unmodified launcher at fixed seed, any NaN/Inf or non-finite grad_norm appears, the smoke fails to reach step 2, or the baseline launcher can no longer train dense GRPO by arguments alone.
