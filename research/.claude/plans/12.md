## Hypothesis

A **same-process** anchor refresh that, every `cadence` trainer steps from a
`delay_K`-stale weight snapshot (smoke `cadence=1`, `delay_K=1`), (i) takes the
**rollout-expanded GRPO actor batch** (`responses`, `response_mask`,
`old_log_probs`, `advantages`, optional `ref_log_prob`), (ii) runs **one
UNMASKED GRPO-actor-loss** forward/backward — with the activation masker
**disabled even though it executes on the actor-train path** — to produce clean
per-target gradients `G_anchor`, (iii) does **no optimizer step** on the anchor
pass, (iv) reads `G_anchor` **RAW, before the EXP-7 spectral-correction hook**,
into the anchor EMA `M_anchor` (`beta_anc=0.95`) and refreshes its SVD **once**,
and (v) **caches that basis for reuse across all fast PPO mini-batches** until
the next refresh — produces, within a **5-step** smoke:

- `comm_eff/anchor_backwards >= 2` (≈4 expected at `cadence=1` over 5 steps),
- a populated `M_anchor`/SVD cache (>= 1 nonzero singular value per targeted
  matrix) that **demonstrably evolves across >= 2 refreshes**
  (`||M_anchor@last − M_anchor@first|| > 0`),
- finite anchor gradient statistics,
- **`comm_eff/anchor_mask_applications == 0`** (the anchor pass fires zero mask
  hooks despite being on the train path — the *unmasked* guard),
- **`comm_eff/anchor_grad_corrected == 0`** (the anchor gradient never passes
  through `correct_matrix` — the *uncorrected* guard),
- **zero** new responses generated and **zero** reward recomputation,
- **zero** optimizer steps on the anchor pass.

The EMA/SVD storage is **config-driven** (`spectral.ema_device`,
`spectral.svd_mode`, `spectral.basis_cache`). The faithful default
(full thin SVD / HBM EMA / cached basis) and a **memory-lean** variant
(CPU-offloaded EMA + low-rank SVD over the full target set) both reach
`global_step == 5` with finite grads and a firing anchor.

**Falsified if** no anchor gradient is produced/cached within 5 steps, the
anchor pass is masked (`anchor_mask_applications > 0`), the anchor gradient is
itself spectrally corrected (`anchor_grad_corrected > 0`), the anchor pass
generates rollouts / recomputes rewards / uses a supervised next-token loss, the
anchor pass takes an optimizer step, or anchor backward produces NaN/Inf —
**OR** if the autograd-hook collision from EXP-8 recurs (a new fail mode for
this lineage).

## next_actions (verbatim from `runs/EXP-8/verdict.md`, captured in commit 72730462)

```yaml
- knob: anchor_backward_graph_isolation
  from: live_fsdp_module
  to: cloned_no_hook_module
  rationale: |
    The anchor `loss.backward()` at engine/fsdp/transformer_impl.py:717 is
    invoked from `_maybe_comm_eff_anchor_refresh` (line 869) on the actor's
    FSDP1-wrapped module. That backward fires FSDP1's
    `_post_backward_hook -> _reduce_grad -> _accumulate_sharded_grad`, which
    reads `flat_param._saved_grad_shard.shape` — but `_saved_grad_shard` is
    `None` outside the fast-path's backward window, so it raises
    `AttributeError: 'NoneType' object has no attribute 'shape'`.
    Break the autograd-hook chain by running the anchor on a deep-cloned
    module whose parameters are detached from the FSDP registration (clone
    params off the optimizer group, off the FSDP `_handles`), OR wrap the
    anchor fwd/bwd inside `FSDP.no_sync()` + `summon_full_params()` with
    `_post_backward_hooks` explicitly suppressed for the duration of the
    anchor pass. Either path satisfies the snapshot guard "snapshot OFF the
    optimizer's parameter group" (a cloned no-hook module is by construction
    off the FSDP fast-path graph).
- knob: anchor_optimizer_param_group
  from: shared
  to: disjoint
  rationale: |
    Defensive belt-and-braces with the cloned-module change: ensure the
    snapshot parameters do not appear in the live optimizer's
    `param_groups`, and are not registered with the FSDP `_handles` /
    `_root_pre_forward_handles`. Independently required by criterion 7
    (`anchor_optimizer_steps == 0`, snapshot off the optimizer's parameter
    group). Verifying disjoint-param-group post-clone is cheap and prevents
    a class of regressions if the cloned module accidentally shares storage
    with a live FSDP-handled `FlatParameter`.
```

    exactly as EXP-7/EXP-8 handled it.
- **FSDP1 autograd-hook chain (the load-bearing source for THIS REVISE).** When
  the fast-path enters `train_batch`, FSDP1 registers `_post_backward_hook` on
  each `FlatParameter`'s post-accumulate-grad hook (per
  `torch.distributed.fsdp/_runtime_utils.py`). That hook calls `_reduce_grad`,
  which calls `_accumulate_sharded_grad`, which calls
  `_check_grad_to_accumulate(sharded_grad, flat_param._saved_grad_shard)`.
  `_saved_grad_shard` is set up by the fast-path's pre-backward and torn down
  after the optimizer step. The anchor's backward fires the SAME hook because
  the cloned-but-still-FSDP-wrapped params are part of the same graph — they
  reach `_check_grad_to_accumulate` against a `None` `_saved_grad_shard`. The
  fix: the anchor pass must NOT trigger FSDP1's post-backward hook.
- **Cell 2 is the EXP-7 reproduction control** (kept as a regression cell in
  this REVISE — see §Experiment design). It already passes; we carry it
  forward to confirm the fix does not regress the anchor-off path.
- **Config-schema (resolved by EXP-8 already).** `CommEffAnchorConfig` has
  `cadence:int`, `delay_K:int`; `CommEffSpectralConfig` has `ema_device`,
  `svd_mode`, `basis_cache` with `__post_init__` validation. EXP-12 carries
  these forward from EXP-8's commits (cherry-picked from
  `origin/exp/8-anchor-circuit @ 5997774e`).
- **EMA / SVD storage memory hierarchy** (drives the lean cell): `M_anchor`
  touched only at refresh ⇒ safe to CPU-offload. SVD basis touched every fast
  PPO mini-batch ⇒ must stay on-GPU during the refresh window. Low-rank
  shrinks both from `O(m·k)` to `O(m·r)`. Lean combo = **CPU EMA + low-rank
  basis cached on GPU**.

sweep_grid:
  # No multi-value performance sweep. Three single-purpose integration cells.
  # The anchor cadence is pinned (cadence=1, delay_K=1) so an anchor provably
  # arrives inside a 5-step window. Design axes: (a) anchor enabled vs disabled
  # (the EXP-7 regression) and (b) faithful vs memory-lean storage.

      comm_eff.spectral.basis_cache: cache         # compute U/S/V once per refresh, reuse across fast mini-batches
      comm_eff.spectral.max_targets: 4             # cheap; proves correctness + guards + EMA evolution
    - name: m2-anchor-off               # CELL 2 — anchor-OFF regression (reproduces EXP-7 spectral path)
      comm_eff.anchor.enabled: false
      comm_eff.spectral.seed_anchor_cache: true    # EXP-7 used seeded basis — reproduce it

    - name: m2-anchor-lean              # CELL 3 — memory-lean storage under realistic target load
      comm_eff.anchor.enabled: true
      comm_eff.spectral.seed_anchor_cache: false
      comm_eff.spectral.ema_device: cpu            # EMA offloaded to (pinned) CPU
      comm_eff.spectral.svd_mode: lowrank          # torch.svd_lowrank(q=rank)
      comm_eff.spectral.rank: 8
      comm_eff.spectral.basis_cache: cache
      comm_eff.spectral.max_targets: -1            # ALL 2D decoder matrices (~196 for L=28)
baselines:
  - dense                              # EXP-3, id-only — regression reduces to anchor.enabled=false (cell 2)
ablations:
  - disable_anchor                     # cell 2 — EXP-7/dense reproduction (criterion 9)
