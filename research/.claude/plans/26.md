## Hypothesis

On the fixed GSM8K surface (Qwen2.5-1.5B-Instruct, vanilla GRPO no-KL/no-entropy, lr 1e-6,
train_batch 128, ppo_mini 64, n=8, max_response 16384, anchor on + owns `Q`, PowerSGD r=77,
cadence/delay_K 5, no clean step), the #25 lag (0.047 below dense, 0.035 below plain PowerSGD)
is caused by the **merger corrupting the live GRPO update DIRECTION**, not by rank-77 PowerSGD
compression (which ties dense at 0.7415). Step A (a real-gradient geometry audit on fp32 tensors)
will show **(a)** plain-PowerSGD update cosine to dense `cos(G_dense, G_comp) >= 0.95` post-warmup
while `signed_ema` update cosine `cos(G_dense, G_corr)` collapses, and **(b)** whether the
activation-energy basis `Q_act` also under-captures off-principal GRPO **update** energy. A
direction-preserving error-feedback PowerSGD merger (Step B, `correction_mode=ef_powersgd`, no
sign term) then recovers `val@50` into the PowerSGD/fresh-clean band, `val@50 >= 0.7414`
(= floor+0.05, within ~1 pt of A0 0.7415), WITHOUT any length/clip collapse.

**FALSIFIED for a given merger** if its best arm `val@50 <= floor+0.02 = 0.7114` OR its
dense-vs-compressed update cosine `cos(G_dense, G_corr)` does not improve over plain PowerSGD's
`cos(G_dense, G_comp)`. (`floor = 0.6914` = no-refresh PowerSGD r=77, EXP-23 A1.)

## Correctness invariants (pre-run gate — REQUIRED, `code_change: true`)

Before Step A spends GPU-hours dumping tensors, and before Step B/C spend a sweep, the new code
must prove it is *correct*. The runner verifies these in a 1–2 step probe on the box; a
`hard`-gate failure aborts before the expensive work (see `## Analyst predicate`). The runner is
**expected** to hit backend-integration bugs on first launch (FSDP sharding, activation
checkpointing, dtype, the parallel uncompressed backward, autograd on the residual) and to run
the commit-hotfix loop on the `exp/*` branch — edit → re-probe → repeat — until every `hard` gate
is green. See `## Notes for runner` for the named failure surfaces.

```yaml
invariants:
  # ---- bind ALL of Step A / B / C / E (instrumentation + new code must be off-path-clean) ----
  - name:  off-path parity (capture instrumentation)
    check: "with capture flags OFF (and correction_mode=signed_ema or none), per-step loss / grad_norm / reconstruction_rel_error are bit-identical to the EXP-25 / plain-PowerSGD path at step 1-3 — the tensor-dump hooks add NO numerical side effect, only I/O"
    gate:  hard
  - name:  measurement-only probes never feed the optimizer (REALISM invariant, machine-checkable)
    check: "the parallel uncompressed `G_dense` backward and the `delay_K=0` fresh-anchor gradient are captured but the optimizer state delta with vs without these probes enabled is bit-identical (probe write-path is detached / dump-only); counters confirm `optimizer_consumed_dense_grad=0`, `optimizer_consumed_freshK0_grad=0`"
    gate:  hard
  # ---- bind the TRAINING path of EVERY arm (the three non-negotiable realism invariants) ----
  - name:  anchor owns Q (fast path read-only)
    check: "across the probe, `powersgd_basis_updates==0` on the fast/training net (fast `maybe_update_basis` is fail-closed) AND `anchor_q_updates>0`; `[bcast] Q updated=True cross_rank_max_rel_dev=0.0` — Q changes ONLY inside the anchor and is broadcast identically across DP ranks"
    gate:  hard
  - name:  full uncompressed pass lives ONLY in the anchor
    check: "the only uncompressed full-coverage gradient pass is the anchor's (`anchor_backwards>0`, full 196-matrix coverage, DP-mean-reduced); the fast/training path is ALWAYS compressed — `clean_cadence=0`, no fresh full-rank clean step ever runs on the fast net (`fast_clean_steps==0`)"
    gate:  hard
  - name:  mandatory anchor staleness
    check: "the training config has `anchor.delay_K>=5` (optimizer ticks); `delay_K=0` is forbidden as a TRAINING config and appears ONLY as a removed measurement probe (see above)"
    gate:  hard
  # ---- bind Step B (the new ef_powersgd merger) ----
  - name:  EF residual limiting-case identity
    check: "with the residual disabled (decay=0 / clip=0), `correction_mode=ef_powersgd` is bit-identical to plain PowerSGD (G_corr == G_comp) — the error-feedback path reduces to a no-op at its limiting setting"

    check: "the ef_powersgd write-back never multiplies by sign(M) / sign(anchor); a static check of spectral_filter.py + a runtime assert that `G_corr` shares the sign of `G_comp` on the dropped-residual re-injection (direction-preserving, not sign-replacing)"
    gate:  hard

    check: "residual `e_t` resets to 0 on target shape mismatch (no stale carry across shape change), is norm-clipped relative to activation norm (`||e_t||/||h_t||` bounded), and is detached from autograd (no graph leak); probe shows no NaN/Inf in `e_t` and `residual_reset_on_shape_mismatch>0` when shapes change"
    gate:  hard
  # ---- backend integration (binds every arm) ----

    check: "the patched path composes with FSDP1 + gradient checkpointing + bf16 + the added parallel uncompressed backward with NO NaN/Inf/OOM in the 1-3 step probe; same seed ⇒ identical derived state (Q, M) across ranks"
    gate:  hard
  - name:  fp32 dump fidelity
    check: "captured tensors are fp32 and keyed by `(global_step, optimizer_tick, target_name, shape, dtype, norm, rank/projection-stats)`; reconstruction_rel_error computed from the dumped A / Â matches the logged scalar (≈0.024) within 1e-3 — confirms the dump is the real tensor, not a bf16 readout"
    gate:  hard
```

The point is to **fail fast and cheap**: a broken parallel-backward or a residual that leaks into

runner MUST iterate the commit-hotfix loop on the `exp/*` branch until the invariants pass.
Emit `STUCK:` and halt ONLY as a last resort, when a fix needs a design decision or an upstream
change.

### Vast.ai utilization discipline (HARD RULE)

- **One box for the staged sequence where the tier matches.** Step A's 3 audit arms and Step B's
  3 training arms run on the SAME provisioned box (warm docker / verl checkout / GSM8K cache) —
  do NOT tear down + reprovision between the audit and the first training arm. The analyst reads
  Step A's dumped tensors from the laptop (rsynced), decides B vs C, and the runner launches the
  decided arms on the still-warm box.
- **Known-idle gap (loosen the GPU-stall watchdog).** Between Step A finishing its capture run
  and the analyst returning the A-decision, the box may sit idle while tensors rsync + the audit
  script runs on the laptop. This is a DESIGNED idle phase — see `## Notes for runner`; the
  `training-log-monitor` thresholds must be loosened for that window so it does not tear the box
  down before Step B launches. (If the analyst turnaround is long, the operator may instead tear
  down after Step A and reprovision for B — acceptable, but the warm-box path is preferred.)
- **Tear down the instant the science is captured.** When the last cell of the launched stage
  writes its done.flag and metrics + tensor dumps are rsynced to `runs/EXP-26/`, the runner /
  Stop hook tears down on the next tick. No "leave it up for the analyst."
- **No keep-alive.** State lives in `runs/EXP-26/` on the laptop (tensor dumps under
  `runs/EXP-26/captures/`, metrics under `runs/EXP-26/metrics/`), never in `/workspace/`.
- **Heartbeat caveat (memory):** the no-heartbeat auto-teardown reads
  `runs/EXP-26/metrics/incoming.log` mtime, which rsync keeps fresh even if training is dead —
  on a cell-done or sustained-GPU-idle signal the runner MUST teardown manually, not wait for the
  backstop.

## Analyst predicate
- **PASS** iff every box in `## Success criteria` that applies to the stage reached is checked.
  For the WHOLE issue: Step A emits a clean DECISION AND the promoted method (B, or C) clears
  `val@50 >= 0.7414` with improved update cosine, no collapse, and a measured comm saving (E).
- **REVISE** if at most `iterations` boxes are unchecked AND the analyst can name a concrete
  next-action knob for each. Output `next_actions:` as a yaml list of
  `{knob, from, to, rationale}`. Allowed REVISE knobs: ef residual `clip` / `decay`; `q_basis`
  selection (Step C); step_target 50→100. **Forbidden as a "fix":** anything that reintroduces
  sign-replacement, changes the GRPO objective/verifier, relaxes a realism invariant, or adds a
  KL/entropy/length cap to the control surface (those may appear ONLY as explicitly-labeled
  guardrail diagnostics on a SEPARATE lineage, never folded in here).
- **STOP** if the hypothesis is falsified (best arm `val@50 <= floor+0.02 = 0.7114` OR
  `cos(G_dense, G_corr)` does not improve over plain PowerSGD) OR a `## Stop conditions` trigger
  fires OR budget exhausted OR `iterations` REVISE cycles already consumed on this lineage.
- **Pre-run gate**: a `hard`-gate failure in `## Correctness invariants` is an automatic **STOP**
  for that run — the implementation is broken (e.g. the probe leaks into the optimizer, a realism
