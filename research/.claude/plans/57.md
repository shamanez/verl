## Hypothesis

Acceptance test (collection unit — the "hypothesis" is a set of operational + correctness invariants, which count as numeric falsifiability). The run is **ACCEPTED (PASS)** iff all five gates hold on the synced artifacts:

1. **fp32 fidelity fired** — every row of `full_manifest.jsonl` reports `dump_dtype == "fp32"` (NOT `"bf16"`), confirming the saved tensors are the true fp32 master weights, not rounded bf16.
2. **widened instrument fired** — every snapshot row reports `n_matrices == 338` (the FULL model: decoder linears PLUS token embeddings, RMSNorm gains, attention biases and lm_head), each 2-D matrix keeping its real shape (no sketch, no subset).
3. **full trajectory present** — the run reaches **80 global steps = 160 optimizer ticks**, with all **160** per-tick snapshots published to R2 and R2-verified. (Per-tick cadence, matching EXP-43: `full/tick_<N>.pt`, key `.../full/tick_<N>/tick_<N>.pt`. The "per-step trajectory" = the first tick of each global step, a subset of the 160-point set.)
4. **dense regime verified codec-OFF** — `comm_eff` counters are zero on every step (`powersgd_applications == 0`, `anchor_backwards == 0`, `spectral_corrections == 0`), i.e. byte-identical to upstream verl (regime A, `COMM_EFF_ENABLED=false`).
5. **integrity clean** — `verify_full_weight_dump.py <weights_dir> --r2` exits **PASS** (sampled snapshots load from R2, `n_matrices == 338`, real shapes preserved, `max_rel_norm_err <= tol`); `r2_manifest.jsonl` has **160/160** rows with `verified: true`; and NO NaN/Inf anywhere in the trajectory (no non-finite `fro_norm` in any manifest row; loss/grad_norm finite on every training step).

**FAILED / STUCK** if: the manifest dtype stays `bf16`; `n_matrices != 338` on any snapshot; the run cannot reach 80 steps on the provisioned box; or R2 verification fails (integrity / count / shape / norm-error).

The single change from EXP-43 is `dump_dtype = fp32` (config-only, one flag). Downstream, this fp32 trace becomes the `<trace_dir>` that the #44 weight-projection engine + the #45–#56 offline replay are re-pointed at for the full-fidelity re-run (the engine is trace-dtype-agnostic; no code change, just a `<trace_dir>` swap).

## Notes for analyst
- This is a **collection unit** — PASS = ACCEPTED, and there is no baseline-comparison metric. The verdict's job is to certify the trace is (a) fp32, (b) full-model (338 matrices), (c) complete (160 ticks), (d) R2-verified, (e) codec-OFF, (f) NaN/Inf-free — and to record the fp32 `<trace_dir>` for #44–#56.
- **fp32-size sanity is a specific, high-value check.** A bf16 tensor relabelled `fp32` in the manifest would pass a naive dtype-string check but is the exact failure this run exists to prevent. Cross-check `remote_bytes` in `r2_manifest.jsonl`: fp32 snapshots must be ~2× EXP-43's bf16 (~6.2 GB vs ~3.1 GB). If snapshots are ~3.1 GB but the manifest says `fp32`, that is a STOP (the dump is not truly fp32).
- Weight the R2 verification (`--r2` sample-download) as the load-bearing gate — the local manifests can look perfect while the R2 objects are truncated/missing. `verified: true` + `local_bytes == remote_bytes` on 160/160 rows AND a PASS from a sample re-download together certify the trace.
- Confirm the R2 prefix is `EXP-57` (not `EXP-43`) — a mislocated or clobbering prefix invalidates both traces.
