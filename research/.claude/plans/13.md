## Hypothesis

The comm-eff dry-run's **step-1 `actor/grad_norm` ≈ 1134** (≈3000× the dense
reference of 0.36 at identical batch knobs) is dominated by **one
identifiable, step-1-present mechanism** among candidates B–G, and that
mechanism is isolable by toggling a single knob while holding the rest of the
method fixed. Concretely, this investigation is falsifiable against these
numeric predicates evaluated at **trainer step 1**:

1. **Scaffold is clean (GATE, Test 1):** with `comm_eff.enabled=false` at
   baseline batch knobs, the disabled path reproduces the dense step-1 shape —
   Cell A `actor/grad_norm` within `0.36 ± 0.10`, `actor/entropy` within
   `0.37 ± 0.10`, `critic/score/mean` within `0.12 ± 0.05`; and Cell B
   (scaffold present, comm-eff off, KL off) `actor/grad_norm` within `±0.10`
   of Cell A (and in absolute terms `<= 1.0`). If Cell B step-1 grad_norm
   `> 1.0`, the scaffolding itself regressed and the investigation pauses
   before Tests 2–4.
2. **A dominant cause is identified** iff some downstream test produces a
   **step-1 `actor/grad_norm` ratio of the "current/default" cell over its
   isolating cell `>= 3×`** (Tests 2, 3 — the toggle that removes most of the
   explosion names the dominant numeric cause), OR Test 4's structural audit
   logs a concrete correctness defect (silent DTensor/Tensor mis-typing,
   anchor target-match count mismatch, hook firing before the FSDP all-reduce,
   or a target `M_anchor` condition number `> 1e6`).

The hypothesis is **falsified / inconclusive** (→ STOP with "no single
dominant cause") if Tests 2 and 3 each show their current-vs-isolating cells
within `< 1.5×` at step 1 AND Test 4's audit surfaces no structural defect —
i.e. the explosion is diffuse across multiple mechanisms and no single
knob/module accounts for it.

## Experiment sequence (REQUIRED when tuning / testing / comparing)

Run **strictly in order on a single provisioned box**. The conditional
progression IS the fail-fast learning loop: each verdict prunes the remaining
search before any more GPU-hr is spent. The runner evaluates each test's
headline-metric predicate inline (from the rsynced metrics) and decides
whether to launch the next test — **no human gate between tests**.

```yaml
sequence:
  - id:        1
    name:      scaffold-noop-at-baseline-knobs   # the GATE
    goal:      "Does comm_eff.enabled=false reproduce the dense step-1 shape at baseline batch knobs, AND does the dense baseline itself reproduce on this branch?"
    config:    "TWO cells, baseline batch knobs (mini=64, wedge=36864, util=0.4, total_epochs=2, val_before_train=True, test_freq=25), use_orig_params=true, 25 trainer steps each. Cell A: comm_eff.enabled=false, use_kl_loss=True, kl_loss_coef=0.001 (dense-reference reproduction). Cell B: comm_eff.enabled=false, use_kl_loss=False, kl_loss_coef=0 (scaffold-noop). On 8×H100: A+B concurrent (4 GPUs each, all 8 busy). On 4×H200: A then B back-to-back, 4 GPUs each."
    success:   "Cell A step-1 grad_norm in 0.36±0.10 AND entropy in 0.37±0.10 AND score in 0.12±0.05; AND Cell B step-1 grad_norm within ±0.10 of Cell A (and <= 1.0). => GATE PASS."
    on_fail:   "stop — if Cell B grad_norm > 1.0 the scaffold regressed (likely FSDP/use_orig_params/schema, cause D); pause investigation, do NOT run Tests 2-4 (they would conflate scaffold bug with method).   - id:        2
    name:      mask-recompute-isolates-step-1-IS-variance   # cause B
    depends_on: 1
    goal:      "Does IS-variance under independent PRF masks (cause B) explain the step-1 grad_norm? The PRF key differs between the actor-train forward and the compute_log_prob recompute by design, so r=exp(log_p_current - log_p_old) != 1 at step 1 even though pi_new == pi_old."
    config:    "TWO cells, baseline batch knobs (mini=64, wedge=36864, util=0.4), no KL, no entropy, full comm-eff otherwise (p=0.9, alpha=0.5, tau=0.01, cadence=5, beta_anc=0.9). Cell B: mask.mask_recompute=false (mask only on actor-train forward; compute_log_prob runs unmasked => clean log_p_old). 10 trainer steps each. Provision 8×H100/H200 for anchor-clone headroom (cause G — restore baseline batch knobs so small-batch variance does not confound)."
    success:   "Cell A step-1 grad_norm / Cell B step-1 grad_norm >= 3× => cause B is the dominant step-1 driver (fix: share PRF keys across the two paths, or disable mask_recompute)."
    on_fail:   "if Cell A ≈ Cell B (ratio < 1.5×), cause B is NOT dominant — proceed to Test 3. (1.5×–3× = partial; record and proceed to Test 3.)"

    name:      spectral-conditioning-at-startup   # causes C and F
    depends_on: 2
    goal:      "Is the spectral filter's behavior on an empty / poorly-conditioned M_anchor (cause C empty-basis at startup, cause F amplification at alpha=0.5) contributing to early-substep grad_norm?"

    success:   "Cell A step-1 grad_norm << Cell B (B/A >= 3×) => spectral correction amplifies (cause F real; lower alpha / raise tau).     on_fail:   "if A ≈ B ≈ C (all within < 1.5×), causes C and F not dominant — proceed to Test 4."
  - id:        4
    name:      fsdp-spectral-integration-audit   # causes D and E (diagnostic, minimal training)
    depends_on: 3
    goal:      "Are causes D (FSDP integration: hook reads p.grad before all-reduce / mixed DTensor-vs-Tensor matching) and E (anchor harvest correctness: silent target-match miss) producing silent shape inconsistencies or silent no-ops?"
    config:    "TWO cells, baseline batch knobs (mini=64, wedge=36864, util=0.4), no KL, no entropy. Cell A: comm_eff.enabled=false (baseline grad shape + FSDP behavior; same config as Test 1 Cell B).     success:   "STRUCTURAL verdict (not numeric): any target silently mis-typed (DTensor vs Tensor) => cause D(b); anchor harvest's three target counts differ => cause E; spectral hook sees p.grad before the FSDP all-reduce completes => cause D(a); any target M_anchor condition number > 1e6 => cause F. Rules honored: runs numbered 1–4; every run after #1 declares `depends_on:`
```
so the analyst short-circuits on a hard failure of an earlier step; Test 1's
two cells are `parallel_with` each other on the 8×H100 tier (concurrent,
4 GPUs each) or sequential on 4×H200.

## Experiment design
```yaml
# This is a diagnostic toggle-isolation, not a hyperparameter sweep. Each test
# toggles exactly ONE knob against the comm-eff default to isolate a candidate
# cause. The cells are enumerated per-test in ## Experiment sequence above.
sweep_grid:
  # Test 1 (gate):  comm_eff.enabled=false × {use_kl_loss=True/kl=0.001, use_kl_loss=False/kl=0}
  # Test 2 (causeB): comm_eff.mask.mask_recompute: [true, false]
  # Test 3 (causeC/F): {alpha=1.0,seed=false} | {alpha=0.5,seed=false} | {alpha=0.5,seed=true}
  # Test 4 (causeD/E): comm_eff.enabled: [false, true(instrumented)]
  isolated_knobs: [mask.mask_recompute, spectral.alpha, spectral.seed_anchor_cache, comm_eff.enabled]
baselines:
  - dense                          # Test 1 Cell A — dense reference (WITH KL), the step-1 grad_norm=0.36 anchor
  - scaffold_noop                  # Test 1 Cell B / Test 4 Cell A — comm_eff.enabled=false, the disabled-path control
ablations:
  - mask_recompute_false           # Test 2 Cell B
  - spectral_alpha_1p0             # Test 3 Cell A (spectral no-op)
  - spectral_seed_anchor_cache     # Test 3 Cell C (seeded basis)
seed_replicates:  1                # step-1 grad_norm is deterministic given the same data order + seed; replicates would burn GPU-hr without sharpening the headline ratio. Cross-cell comparison is same-seed by construction.
fanout_max:       2                # Test 1 fans out to 2 concurrent cells on 8×H100; all other tests run cells back-to-back on the single box.
```

### Vast.ai utilization discipline (HARD RULE)

- **One instance for the entire Test 1→4 sequence.** Provision a single box on
  the standard default tier up front and chain all tests back-to-back (shared
  docker / verl checkout / dataset cache). Tearing down + reprovisioning
  between sequential tests is forbidden.
- **Keep every GPU busy.** On the **8×H100** tier, Test 1's two 4-GPU cells
  (A + B) run as **concurrent** tmux sessions (4 GPUs each → all 8 busy). On
  the **4×H200** tier they run **back-to-back**, each using all 4 GPUs. Tests
  2–4 use the full box per cell, cells back-to-back. No GPU idles.
- **Fail-fast on the gate.** If Test 1 fails the gate (Cell B step-1
  `grad_norm` > 1.0, or Cell A out of tolerance), short-circuit — do NOT spend
  GPU-hr on Tests 2–4; tear down immediately.
- **Tear down the instant the science is captured.** When the lineage resolves
  (a dominant cause is identified, OR all four tests are exhausted) and the
  last cell's metrics are rsynced to the laptop, the runner / Stop hook tears
  down within the next tick. State lives in `runs/EXP-13/` on the laptop, not
  in `/workspace/` on the box. No keep-alive.

## Success criteria

The plan's overall deliverable is a **root-cause verdict**, so the headline
criteria are the gate + the dominant-cause identification predicate. The
analyst greps `runs/EXP-13/metrics/*.jsonl` (and the Test-4 diagnostic logs)
for these values.

- [ ] **GATE (Test 1):** Cell A step-1 `actor/grad_norm` ∈ [0.26, 0.46] AND `actor/entropy` ∈ [0.27, 0.47] AND `critic/score/mean` ∈ [0.07, 0.17] (dense reference reproduced on this branch).
- [ ] **GATE (Test 1):** Cell B step-1 `actor/grad_norm` within ±0.10 of Cell A AND ≤ 1.0 (scaffolding with comm-eff disabled does not regress the no-comm-eff path).
- [ ] **Every launched cell reaches its `steps_per_cell` target with finite gradients** — no NaN/Inf in `actor/grad_norm`, `actor/pg_loss`, or `actor/entropy` at any logged step in any cell.
- [ ] **Dominant cause identified** — at least one of: Test 2 `grad_norm(A)/grad_norm(B) ≥ 3×` at step 1 (cause B); Test 3 `grad_norm(B)/grad_norm(A) ≥ 3×` at step 1 (cause F) OR `grad_norm(B)/grad_norm(C) ≥ 3×` at steps 1–5 (cause C); Test 4 structural log shows a DTensor/Tensor mis-typing, an anchor target-match count mismatch, a hook firing pre-all-reduce, or a target `M_anchor` condition number > 1e6 (cause D/E/F).
- [ ] **Verdict names the dominant cause (one of B–G) AND the specific target module path + knob for the follow-up fix** (e.g. `verl/workers/comm_eff/activation_mask.py` + share PRF key across the two forwards). On a no-dominant-cause outcome, the verdict instead enumerates what was ruled out and emits STOP.

These criteria are machine-checkable: the first four are numeric grep targets;
the fifth is satisfied by the analyst's verdict explicitly naming a cause-id
∈ {B,C,D,E,F,G} (or STOP/no-dominant) and a `verl/...` path + knob.

## Analyst predicate
- **PASS** iff the GATE criteria hold (Test 1 Cells A and B in tolerance) AND
  a dominant cause is identified (one of the Test 2/3/4 dominant-cause boxes
  checked) AND the verdict names that cause-id plus a `verl/...` target module
  + knob. A PASS here means "the investigation succeeded — root cause found";
  it does NOT mean the bug is fixed.
- **REVISE** if at most `iterations` boxes are unchecked AND the analyst can
  name a concrete next-action knob change for each (e.g. "Test 2 ratio was
  2.1× — partial; widen to mask.p ∈ {0.5, 0.9} to sharpen the IS-variance
  signal"). Output `next_actions:` as a yaml list of
  `{knob, from, to, rationale}` objects. REVISE is the right verdict when a
  test is *inconclusive* (ratio in 1.5×–3×) rather than failed.
- **STOP** if (a) the GATE fails — Test 1 Cell B step-1 grad_norm > 1.0 (scaffold
  regressed; the fix targets the FSDP integration, cause D — investigation
  pauses for a parity-restore experiment) or Cell A out of tolerance (branch
  does not reproduce dense baseline); OR (b) all four tests ran and no single
  dominant cause surfaced (hypothesis falsified — "diffuse, no dominant
  mechanism"; verdict lists what was ruled out); OR (c) budget exhausted; OR
  (d) `iterations` REVISE cycles already consumed on this lineage.
