This is an **ablation**: it varies one knob (`beta_anc`) on an already-characterized merger (`signed_ema alpha=0.5`) to close the question of whether mild anchor averaging helps. It is `code_change: false` — every knob it touches already exists in the dataclass and the canonical launcher; it is set via Hydra last-wins passthrough. It runs on Vast (3 short training cells).

## Hypothesis

For the `signed_ema` merger at the reference dose `alpha=0.5`, mild anchor-gradient averaging (`beta_anc > 0`, which smooths the per-matrix EMA `M` whose `sign(M)` the merger consumes) might stabilize the stale anchor sign enough to lift greedy GSM8K val@50 above the `beta_anc=0` signed-EMA reference. The falsifiable test: sweeping `beta_anc ∈ {0.25, 0.50, 0.75}` (all other knobs B2-fixed; `alpha=0.5` held constant), the best beta cell beats the EXP-32 `signed_ema alpha=0.5 beta_anc=0` reference (val@50 ≈ 0.7271) by **more than the project single-draw eval-noise bar of 0.024**:

```text
success threshold:  best( val@50 | beta_anc ∈ {0.25, 0.50, 0.75} )  -  0.7271  >  0.024
                    i.e.  best beta cell val@50  >  0.7511
```

If every cell ties or regresses within ±0.024 of 0.7271, the hypothesis is **falsified**: `beta_anc` is not worth pursuing for signed EMA, and `beta_anc=0` stays the signed-EMA reference setting. (This mirrors the EXP-33 finding that `beta_anc` is a flat free-averaging tie on the *delayed_ef* merger; this run asks the same question on the *signed_ema* merger and is expected to also be NULL-for-surpass — but the sweep is cheap enough to close it cleanly rather than leave it inferred.)

Secondary correctness gate (not the headline): no NaN/Inf in any loss field, no reward-hack length ignition, no training collapse on any cell.
