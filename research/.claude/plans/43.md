## The measurement (unchanged from the original plan)
`anchor_align_cos` compares against `g_live` on a DIFFERENT batch (conflates weight-staleness with
batch-difference). This holds the batch fixed. Per fire, per-matrix over the 196 decoder matrices:
- **`grad_proj_gain = cos(g_proj,g_now) − cos(g_stale,g_now)`  ← HEADLINE** — is projection making
  the gradient more accurate?
- `grad_proj_relerr`, `grad_stale_relerr`; `weight_proj_ratio` (cross-checks EXP-42 online).
- per-matrix p10/p50/p90 of `grad_proj_gain` (WHERE it helps).
Cost: +2 detached backwards/fire (proj), +1/fire (no-proj). ~negligible.

## Analyst predicate
- **PASS** iff a projection run shows median `grad_proj_gain > +0.02` AND `val >=` no-proj without
  collapse (projection BOTH accurate AND useful).
- **REVISE** if accurate (`grad_proj_gain > +0.02`) but not converting — next knob: `beta_anc`
  0.50→{0.25,0.10}, then a shorter-horizon α.
- **STOP** if median `grad_proj_gain ≤ 0` for BOTH projection runs — linear weight extrapolation
  does not translate into a more accurate gradient on this landscape (the deepest finding for this
  lineage).
