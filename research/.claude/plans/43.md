## Hypothesis

This is a **collection unit**, not a hypothesis test, so the falsifiable thresholds are *acceptance gates on the captured artifact* (operational thresholds count as numeric falsifiability). The run is ACCEPTED iff ALL FOUR hold; any one failing is FAILED/STUCK with the named escalation:

1. **Widened instrument fired** — the observer banner reports `select_all=True` and the first `manifest.jsonl` row reports `n_matrices` ≈ 338 (NOT 196), confirming the decoder linears PLUS the projector-EXCLUDED params (token embeddings, RMSNorm gains, attention biases, `lm_head`) are all sketched. (If `n_matrices` stays 196 the widened flag did not take effect → STUCK.)
2. **Trajectory length** — the regime-A cell reaches ≥ 80 training steps (= 160 optimizer ticks at batch 128 / mini 64 = 2 ticks/step) with no NaN/Inf in any loss field, yielding ≥ ~115 valid anchor points at the longest calib horizon (h=20) for stable horizon-grid statistics. (Cannot reach 80 steps on the provisioned box → STUCK; relaunch once within the iteration budget.)
3. **Sketch fidelity** — the sketch-derived `weight_proj_ratio` matches the on-box EXACT fp32 `calib.jsonl` headline scalars within **5% relative** at the calib grid (deltas=[10] × horizons=[5,10,20]). (Rel error > 5% at *every* calib cell → escalate: larger `k` or a bf16 full-snapshot fallback.)
4. **Dense regime verified codec-OFF** — the `comm_eff` counters are all zero: `powersgd_applications=0`, `anchor_backwards=0`, `spectral_corrections=0` (byte-identical to upstream verl on the training path).

DELIVERABLE: the synced read-only trace dir `research/runs/EXP-43/regimeA/weights/` (per-tick `sketch_tick_*.npz` + `manifest.jsonl` + `calib.jsonl`), the WandB run backfilled to the final step, and the ledger row marked TORN_DOWN. **No HTML report from this issue** (reports are downstream).
