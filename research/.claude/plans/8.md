## Hypothesis

A **same-process** anchor refresh that, every `cadence` trainer steps from a
`delay_K`-stale weight snapshot (smoke `cadence=1`, `delay_K=1`), (i) takes the
**rollout-expanded GRPO actor batch** (`responses`, `response_mask`,
`old_log_probs`, `advantages`, optional `ref_log_prob`), (ii) runs **one
UNMASKED GRPO-actor-loss** forward/backward — with the activation masker
**disabled even though it executes on the actor-train path** — to produce clean
per-target gradients `G_anchor`, (iii) does **no optimizer step** on the anchor
pass, (iv) reads `G_anchor` **RAW, before the EXP-7 spectral-correction hook**,
into the anchor EMA `M_anchor` (`beta_anc=0.95`) and refreshes its SVD **once**,
and (v) **caches that basis for reuse across all fast PPO mini-batches** until
the next refresh — produces, within a **5-step** smoke:

- `comm_eff/anchor_backwards >= 2` (≈4 expected at `cadence=1` over 5 steps),
- a populated `M_anchor`/SVD cache (>= 1 nonzero singular value per targeted
  matrix) that **demonstrably evolves across >= 2 refreshes**
  (`||M_anchor@last − M_anchor@first|| > 0`),
- finite anchor gradient statistics,
- **`comm_eff/anchor_mask_applications == 0`** (the anchor pass fires zero mask
  hooks despite being on the train path — the *unmasked* guard),
- **`comm_eff/anchor_grad_corrected == 0`** (the anchor gradient never passes
  through `correct_matrix` — the *uncorrected* guard),
- **zero** new responses generated and **zero** reward recomputation,
- **zero** optimizer steps on the anchor pass.

The EMA/SVD storage is **config-driven** (`spectral.ema_device`,
`spectral.svd_mode`, `spectral.basis_cache`). The faithful default
(full thin SVD / HBM EMA / cached basis) and a **memory-lean** variant
(CPU-offloaded EMA + low-rank SVD over the full target set) both reach
`global_step == 5` with finite grads and a firing anchor.

**Falsified if** no anchor gradient is produced/cached within 5 steps, the
anchor pass is masked (`anchor_mask_applications > 0`), the anchor gradient is
itself spectrally corrected (`anchor_grad_corrected > 0`), the anchor pass
generates rollouts / recomputes rewards / uses a supervised next-token loss, the
anchor pass takes an optimizer step, or anchor backward produces NaN/Inf. These
are operational correctness thresholds (M2 integration smoke), not
algorithm-level performance thresholds — the headline claim is that a clean
K-stale anchor gradient can be produced same-process, **unmasked and never
re-corrected**, without contaminating rollout/reward and without an optimizer
step, and that its EMA/SVD storage can run either in HBM (faithful) or
CPU-offloaded + low-rank (memory-lean).

- Load-bearing facts inherited from EXP-7 (so the runner does not rediscover them):

  - Correction point is `after_actor_backward__before_optimizer_step` — AFTER FSDP reduction, BEFORE grad clipping. The anchor's `G_anchor` extraction and EMA/SVD refresh must sit at the same hook, but the anchor grad is read **before** any `correct_matrix` call (guard 6).
  - `entropy_coeff=0.001` guarantees a nonzero gradient independent of reward variance — keep it so anchor grad stats are not degenerate-zero.
  - sha256-seeded anchor (not salted builtin `hash()`) for cross-rank determinism at `world_size=4`.
  - EXP-3 has **no run dir on disk**; `diff_against_baseline.py` against it will report `baseline not found`. The dense regression therefore reduces to the within-run `comm_eff.anchor.enabled=false` cell (criterion 9 below), exactly as EXP-7 handled it.
- **Config-schema mismatch found at planning (HARD BLOCKER for the launch command).** `verl/workers/config/comm_eff.py:CommEffAnchorConfig` currently exposes `{enabled, every_n_steps, ema_decay}` — it has **no `cadence` and no `delay_K`**, and OmegaConf's structured-config merge **rejects unknown keys**, so the smoke command's `comm_eff.anchor.cadence=1 comm_eff.anchor.delay_K=1` would die at config validation before training. The runner MUST add these fields (see `## Code change`). Also note `anchor.ema_decay=0.99` is currently **unused and contradicts** the paper's `beta_anc=0.95`: the anchor-gradient EMA is owned by the spectral filter (`spectral.beta_anc`), so `anchor.ema_decay` is removed/repurposed, not wired to the EMA.
- **EMA footprint reality (drives the storage layer).** `spectral.max_targets=4` caps correction to 4 matrices today, so the EMA is currently *trivial*; the ~0.6 GB (attention q/k/v/o on 28 layers, fp32) → ~5 GB (incl. MLP gate/up/down) footprint only appears when the cap is lifted (`-1`) for a real / 100-step run (EXP-11). SVD is presently **recomputed every correction** (`spectral_filter.py` calls `torch.linalg.svd` per `correct_matrix`), NOT cached; `spectral.rank=8` exists but is unused. This plan turns the EMA into a real (config-placeable) store, caches the basis per refresh, and gives `rank` meaning under `svd_mode=lowrank`.
- **Memory hierarchy that motivates the knobs:** `M_anchor` (the EMA) is touched **only at refresh** (every `cadence` steps) ⇒ safe to offload to CPU. The SVD basis `U/S/V` is touched **every fast PPO mini-batch** ⇒ must stay on-GPU during the refresh window (cache) or be recomputed; offloading the *basis* would be pathological (per-mini-batch H2D/D2H). Low-rank shrinks both from `O(m·k)` to `O(m·r)`. ⇒ the recommended lean combo is **CPU EMA + low-rank basis cached on GPU**.

## Experiment design
```yaml
sweep_grid:
  # No multi-value performance sweep. Three single-purpose integration cells.
  # The anchor cadence is pinned (cadence=1, delay_K=1) so an anchor provably
  # arrives inside a 5-step window. The design axes are (a) anchor enabled vs
  # disabled (the EXP-7 regression) and (b) faithful vs memory-lean storage.
  cells:
    - name: m2-anchor-faithful          # CELL 1 — headline integrated M95+AP, faithful storage
      comm_eff.anchor.enabled: true
      comm_eff.spectral.seed_anchor_cache: false   # live anchor POPULATES M_anchor (EXP-7 used true; no live anchor then)
      comm_eff.spectral.ema_device: gpu            # HBM (default, faithful)
      comm_eff.spectral.svd_mode: full             # full thin SVD (default, faithful)
      comm_eff.spectral.basis_cache: cache         # compute U/S/V once per refresh, reuse across fast mini-batches
      comm_eff.spectral.max_targets: 4             # cheap; proves correctness + guards + EMA evolution
    - name: m2-anchor-off               # CELL 2 — anchor-OFF regression (reproduces EXP-7 spectral path)
      comm_eff.anchor.enabled: false
      comm_eff.spectral.seed_anchor_cache: true    # EXP-7 used the seeded basis (no live anchor) — reproduce it
      comm_eff.spectral.max_targets: 4
    - name: m2-anchor-lean              # CELL 3 — memory-lean storage under realistic target load
      comm_eff.anchor.enabled: true
      comm_eff.spectral.seed_anchor_cache: false
      comm_eff.spectral.ema_device: cpu            # EMA offloaded to (pinned) CPU, moved to GPU only at refresh
      comm_eff.spectral.svd_mode: lowrank          # torch.svd_lowrank(q=rank) instead of full thin SVD
      comm_eff.spectral.rank: 8
      comm_eff.spectral.basis_cache: cache
      comm_eff.spectral.max_targets: -1            # ALL 2D decoder matrices (~196 for L=28) — actually stresses offload
baselines:
  - dense                              # EXP-3, id-only (no run dir) — regression reduces to anchor.enabled=false within-run (cell 2)
ablations:
  - disable_anchor                     # cell 2: comm_eff.anchor.enabled=false ⇒ EXP-7/dense behavior (criterion 9)
  - memory_lean_storage                # cell 3: CPU EMA + low-rank SVD (criterion 10) — proves the lean path trains

fanout_max:       1
```

## Success criteria
- [ ] `comm_eff/anchor_backwards >= 2` within the 5-step smoke (≈4 expected at cadence=1); anchor refresh fired repeatedly.
- [ ] Anchor EMA/SVD cache populated **by the live anchor** (`seed_anchor_cache=false`): `>= 1` nonzero singular value per targeted matrix after a refresh.
- [ ] **EMA evolves:** `M_anchor` at the last refresh differs from the first (`||ΔM_anchor|| > 0`) — observable only because the window is 5 steps, not 2.
- [ ] **Unmasked-anchor guard:** `comm_eff/anchor_mask_applications == 0` (zero mask hooks fired on the anchor pass even though it runs on the actor-train path).
- [ ] **Uncorrected-anchor guard:** `comm_eff/anchor_grad_corrected == 0` (the anchor gradient is read raw into the EMA and never passes through `correct_matrix` / the spectral hook).
- [ ] `comm_eff/anchor_rollouts_generated == 0` AND `comm_eff/anchor_rewards_recomputed == 0` (no rollout/reward contamination).
- [ ] `comm_eff/anchor_optimizer_steps == 0` (anchor pass never steps the optimizer; snapshot params off the optimizer's parameter group).
- [ ] Anchor gradient stats finite (no NaN/Inf in `comm_eff/anchor_grad*` or `actor/grad_norm`); cell 1 reaches `global_step == 5`.
- [ ] **Anchor-off regression (cell 2):** zero `comm_eff/anchor_*` activity, spectral still fires from the seeded cache (`spectral_corrections > 0`), finite grad_norm, reaches `global_step == 5` — i.e. reproduces EXP-7.
- [ ] **Memory-lean storage (cell 3):** with `ema_device=cpu`, `svd_mode=lowrank`, `max_targets=-1`, the run reaches `global_step == 5` with finite grads and a firing anchor; a log line confirms the EMA tensors live on CPU and `torch.svd_lowrank` was used. Numerical equivalence to cell 1 is **not** required (low-rank differs by design).
- [ ] If `comm_eff/anchor_batch_fraction < 1.0`, the subset/microbatch deviation is logged with a reason (OOM fallback path taken and explained).
- [ ] `tests/workers/comm_eff/test_anchor_queue.py` passes: K-staleness snapshot integrity; anchor reuses GRPO actor-loss (NOT next-token / supervised); no rollout/reward calls; no optimizer step; **anchor runs with `mask_active == False`**; **`G_anchor` is read before any `correct_matrix` call**.
- [ ] `tests/workers/comm_eff/test_spectral_filter.py` gains and passes: `svd_mode=lowrank` rank-r reconstruction error is bounded and decreasing in `rank`; `ema_device=cpu` round-trip yields the same `M_anchor` as on-device; `basis_cache=recompute` is numerically equal to `cache`.

All criteria are machine-checkable. The analyst greps the on-box training log
and `runs/EXP-8/metrics/*.jsonl` (or the inline `[comm_eff][EXP-8]` / `step:N`

`anchor_optimizer_steps`, `anchor_mask_applications`, `anchor_grad_corrected`)
