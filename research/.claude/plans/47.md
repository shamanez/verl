## Hypothesis

The two-anchor **damped-linear** projector

```text
v = theta_t - theta_{t-Delta}
theta_hat_{t+h} = theta_t + lambda * (h / Delta) * v          (0 <= lambda <= 1)
```

with `lambda` chosen **out-of-sample on strictly-earlier windows** from a small fixed
grid, is the correct ANCHOR/FAST linear baseline. The lane is falsifiable by producing a
**decisive, per-group, per-regime** answer to:

1. **Operating point.** In the PRIMARY per-step regime at `(Delta=10, h=10)` global steps,
   does OOS-damped beat **naive linear** (`lambda=1`) and does it beat **hold-stale**
   (GLOBAL median `weight_proj_ratio < 1.0`, i.e. does projection help at all)? Report the
   per-tick `(Delta=20, h=20)` cell too and state it relative to the #45 naive_linear
   reference `1.158` (the per-tick cell IS #45-comparable; per-step numbers are a NEW
   cadence and are not directly comparable to `1.158`).
2. **Does increasing Delta help?** Over the EXTENDED per-tick sweep `Delta ∈ {5,10,20,25,
   35,40}` at the operating `h`, is there a `best_delta` that strictly improves the ratio,
   and does the improvement keep growing past Δ=20 or saturate/reverse? (The #45 per-tick
   readout had `best_delta=5` on the {5,10,20} grid — the extension tests whether wider
   anchors, up to 40, do better or worse.)
3. **h_safe.** The max horizon `h` where the GLOBAL OOS-damped median ratio `< 1.0`, in
   BOTH regimes — reported in **global steps** (per-step) and in ticks (per-tick), so the
   "how far can ANCHOR safely project" answer is in the production unit.
4. **Breakers.** Which `layer_idx` / `block_type` / special group, if any, breaks the
   global conclusion in either regime.
5. **Linearity (the MUST metric).** What is the per-scalar linearity R² of our GRPO run —
   GLOBAL median + `Pr(R²>0.7)`, per `block_type` / `super_block` / `layer_idx`, in BOTH
   regimes — and where does it land vs the Wang et al. 2026 anchors (nearest RL analog
   R1-Distill-Qwen-1.5B GRPO/DeepScaleR `0.845 / 0.794`; SFT Qwen2.5-1.5B+GSM8K
   `0.426 / 0.259`)? Because linearity is reported RL-specific + reward-noise-driven, our
   easier GSM8K GRPO run is an OPEN question — it may land anywhere between the SFT `0.43`
   and RL `0.85` floors. And does R² **predict projectability** — i.e. do high-R² groups
   have lower `weight_proj_ratio` / larger `h_safe` (the R²-vs-ratio coupling that future
   MOAT optimization will steer by)? **A LOW R² answer is a valid, decisive finding, not a
   failure** (it directly informs whether the linear projector is the right family).

Because damping can only shrink the naive-linear overshoot — the grid nests **hold-stale
at lambda=0** and **naive-linear at lambda=1**, so OOS-damped can never be worse than the
better reference on past data (the OOS gap is the honest cost) — **a ratio `> 1` at long
`h`, or "wider Delta never helps", for ALL lambda is a VALID, decisive negative finding,
not a failure.** The lane PASSES by producing a **correct, schema-verified,
machine-readable answer either way, in both regimes**, rendered in the HTML report — not
by damped necessarily winning. It is falsified (STOP) only if the harness/correctness
gates cannot pass or an answer cannot be computed within the iteration budget.

  linearity deliverable (Wang et al. 2026, arXiv:2601.04537) and it rides the SAME one-time
  streaming cache build — **do NOT add a second 987 GB pass.** `stream_stats` already holds,
  per element, `V = Σ_t φ_t` and `W = Σ_t (t − t̄) φ_t` (with `φ_t = θ_t − θ_0`). Add ONE more
  per-element f64 accumulator `P = Σ_t φ_t²` (+8 B/elem within a chunk, ~2n extra flops/tick,
  ZERO extra trace reads). Then per element, with `N = n_ticks` and `S_tt = N(N²−1)/12`:
  - `SS_tot = P − V²/N`   (total SS of φ about its mean over the N snapshots)
  - `SS_reg = W² / S_tt`  (regression SS for the OLS slope `W/S_tt`)
  - `R² = SS_reg / SS_tot`

  φ-accumulator path is valid and is what the parity check must recompute over the SAME N
  snapshots. **Reduce per matrix at chunk end** (while `V`/`W`/`P` are still the per-element
