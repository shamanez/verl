## Hypothesis

Applying deterministic PRF random masks `h_tilde = h * mask` (element-wise, in-graph, **no** `1/(1-p)` rescale) at pipeline-boundary decoder layers **only inside actor-train forward/backward** runs a two-step GRPO smoke (Qwen2.5-1.5B-Instruct / GSM8K) to `global_step=2` with: (1) empirically measured masked-fraction within **±0.02 of the configured `p`** on every targeted boundary (`p=0.90` → measured 0.88–0.92; `p=0.95` → 0.93–0.97); (2) `actor/grad_norm` **finite** on every substep, **no NaN/Inf** in any loss/grad/reward/log-prob field, and **≥1 actor parameter** changed between step 0 and step 2; (3) **zero** mask applications on rollout generation, old log-prob recompute, ref log-prob, validation, checkpoint, and `infer_batch` (`comm_eff/mask_applications` on those paths `== 0`; on the actor-train path `> 0`). **Falsified if** the measured mask ratio deviates > 0.02 from `p`, masks fire on any non-actor-train path, `actor/grad_norm` is non-finite, NaN/Inf appears in any loss/grad/reward/log-prob field, or the mask depends on activation values rather than the PRF key. The masked path must not fork the GRPO algorithm — same rollout, log-prob, reward, advantage, optimizer, weight-sync sequence — and `comm_eff.enabled=false` must still reproduce dense GRPO exactly (EXP-4 no-op contract regression).

## Masking specification (inline — implementer must follow exactly)

- **Form:** `h_tilde = h * mask`, element-wise, in-graph. **No** forward `1/(1-p)` rescaling (Algorithm A writes the direct product; rescaling at `p=0.95` destabilizes bf16). Do **not** overclaim unbiasedness for the no-rescale port.
- **PRF key:** masks come from a shared deterministic PRF whose key includes at least **(layer/boundary id, global optimizer step, microbatch identity, sequence-shard identity when present, hidden size, base run seed)**. The key **must not** depend on activation values. Reproducible across ranks and re-runs.
- **Boundary layers:** derive `L` (num decoder blocks) and hidden size from `model.config` (do NOT hardcode). Partition block indices into `pp_size` shards and take the **last block index of each shard except the final shard**. For `L=16, pp_size=8` this is `[1,3,5,7,9,11,13]`. `pp_size` is a config knob (logical, not a real pipeline split).
- **Top-k masking is forbidden** for this method — random PRF masking is required; top-k introduces structured bias the later spectral filter cannot remove.
- **Substep awareness:** a trainer step reuses one rollout batch over multiple PPO mini-batches, so the PRF key must incorporate optimizer-substep / microbatch identity, not just trainer step.
