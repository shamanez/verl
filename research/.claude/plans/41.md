## Hypothesis

A linear weight extrapolator for the anchor makes the `delay_K=20` anchor signal usable during real GRPO training. On the fast-1K surface (`max_response_length=1024`, PowerSGD r=77, anchor `cadence`/`delay_K=20/20`, merger fixed at `signed_ema` α=0.25 β_anc=0.50), an anchor that computes `g(theta_hat[t])` at an extrapolated weight point — fixed-linear `theta_hat[t] = 2*theta[t-20] - theta[t-40]`, with a learned per-block residual upgrade — instead of `g(theta[t-20])` will (a) reach **100 training steps with no NaN/Inf/OOM, no terminal entropy collapse, and no length explosion** (the raw 20/20 baseline collapses ~step 61), AND (b) **lift the in-training anchor alignment** — `cos(g(theta_hat[t]), g_live)` measured at sync must rise vs the raw stale anchor's `cos(g(theta[t-20]), g_live)`, with the lift being a genuine rotation (off-diagonal), AND (c) reach the **on-surface 5/5 low-latency reference band** (the staleness-removed ceiling measured in this same plan, cell A). Falsified if any cell ignites/collapses by step 100, if alignment does not rise vs the raw stale anchor (a run that merely survives by `signed_ema` damping the anchor toward the dead no-merger floor ≈0.63 is a STOP, not a PASS), or if look-ahead-20/20 does not reach the 5/5 reference band.

## Correctness invariants (pre-run gate — REQUIRED when `code_change: true`)

Before the 100-step sweep is worth a GPU-hour, the look-ahead patch must prove it is *correct*, not merely that it trains. The runner verifies these in a cheap 1–2 step probe (`total_training_steps=2`, look-ahead enabled) BEFORE the full cell; any `hard`-gate failure aborts the cell (see `## Analyst predicate`) and the runner enters the commit-hotfix loop on the `exp/*` branch.

```yaml
invariants:
  - name:  disabled-path parity (off-path no-op)
    check: "with lookahead_anchor=disabled the run is byte/metric-identical to the current comm-eff baseline path on a 2-step probe (same loss, same anchor-fire counters, same M state). A new config knob added to comm_eff.py dataclass MUST also be mirrored in the actor config yaml or it silently no-ops (prior pinned test)."
    gate:  hard
  - name:  fixed-linear limiting-case identity
    check: "in fixed-linear mode theta_hat[t] == 2*theta[t-20] - theta[t-40] EXACTLY (within fp tolerance) for the excluded-param-free blocks, verified against the two retained snapshots; in learned mode initialised at coefficients [a1=1,a2=0,a3=0] the FIRST fire equals the fixed-linear prediction (one code path, frozen=fixed, unfrozen=learned)."
    gate:  hard
  - name:  no leakage (anti-peek)
    check: "the current live theta[t] is NEVER used to construct the current theta_hat[t] before g(theta_hat[t]) is computed; learned coefficients update ONLY from retrospective residuals theta_true[t_prev] - theta_hat[t_prev] at a PRIOR fire. Assert by logging the source ticks (t-20/t-40/t-60...) used per fire and confirming none is >= t."
    gate:  hard
  - name:  anchor isolation
    check: "the look-ahead path triggers NO anchor optimizer step, NO anchor reward recompute, NO anchor rollout generation, NO anchor mask application — only the existing clean unmasked anchor PG backward at theta_hat[t]. Anchor invariant counters stay 0 for all four."
    gate:  hard
  - name:  multi-rank agreement / determinism
    check: "look-ahead coefficients and predicted weights are cross-rank-identical wherever they affect DP-reduced anchor state; same seed ⇒ identical derived theta_hat across ranks (no divergence under the FSDP sharding actually used)."
    gate:  hard
  - name:  bounded memory (no leak)
    check: "snapshot/history retention is bounded and REPORTED. bf16 1.5B ≈ 3 GB/snapshot. Fixed-linear needs 2 (theta[t-20], theta[t-40]); learned d1/d2/d3 needs 4–5 (~12–15 GB CPU) plus possibly one retrospective-residual target. Reuse paired-replay snapshots where possible. No unbounded CPU/HBM growth across fires; peak max_mem logged and within the box."
    gate:  hard
  - name:  backend integration (no NaN/OOM in probe)
    check: "the look-ahead anchor backward composes with FSDP sharding + activation checkpointing + bf16 with no NaN/Inf/OOM in the 2-step probe; anchor backward respects the actor token budget (ppo_max_token_len_per_gpu=24576) and spectral.ema_device=cpu."
    gate:  hard
  - name:  LayerNorm/embedding exclusion
    check: "LayerNorm + embedding (and lm_head/tied-embedding) parameters are EXCLUDED from linear extrapolation (paper Fig 8 / App A.2: norm layers have low linearity); the excluded set is logged and those params take the raw theta[t-20] (no projection). Per-block scope covers only the high-linearity decoder weight matrices."
    gate:  hard
```

The point is to fail fast and cheap on a broken implementation. New code almost always surfaces backend-integration bugs on first launch (sharding / activation-checkpointing / dtype / OOM / autograd). When that happens it is mandatory to iteratively diagnose and FIX it — edit on the `exp/41-*` branch → re-run the 2-step probe → repeat — until the invariants pass. Do not stop at the first error. Emit `STUCK:` and halt only as a genuine last resort (a fix needs a design decision or an upstream change). Likely failure surfaces are named in `## Notes for runner`.
