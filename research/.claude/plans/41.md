## Hypothesis

A linear weight extrapolator for the anchor makes the `delay_K=20` anchor signal usable during real GRPO training. On the fast-1K surface (`max_response_length=1024`, PowerSGD r=77, anchor `cadence`/`delay_K=20/20`, merger fixed at `signed_ema` α=0.25 β_anc=0.50), an anchor that computes `g(theta_hat[t])` at an extrapolated weight point — fixed-linear `theta_hat[t] = 2*theta[t-20] - theta[t-40]`, with a learned per-block residual upgrade — instead of `g(theta[t-20])` will (a) reach **100 training steps with no NaN/Inf/OOM, no terminal entropy collapse, and no length explosion** (the raw 20/20 baseline collapses ~step 61), AND (b) **lift the in-training anchor alignment** — the new scalar `anchor_align_cos = cos(g(theta_hat[t]), g_live)`, where `g_live` is the raw fast-circuit per-target gradient staged BEFORE the merger overwrites it, must rise vs the raw stale anchor's `cos(g(theta[t-K]), g_live)` measured identically in cell A, AND (c) reach the **on-surface 5/5 low-latency reference band** (the staleness-removed ceiling measured in this same plan, cell A). Falsified if any cell ignites/collapses by step 100, if `anchor_align_cos` does not rise vs the raw stale anchor (a run that merely survives by `signed_ema` damping the anchor toward the dead no-merger floor ≈0.63 is a STOP, not a PASS), or if look-ahead-20/20 does not reach the 5/5 reference band.

## Correctness invariants (pre-run gate — REQUIRED when `code_change: true`)

Before the 100-step sweep is worth a GPU-hour, the look-ahead patch must prove it is *correct*, not merely that it trains. The runner verifies these in a cheap **fire-forcing** probe BEFORE each full cell; any `hard`-gate failure aborts the cell (see `## Analyst predicate`) and the runner enters the commit-hotfix loop on the `exp/*` branch.

> **PROBE CONFIG (must-fix #6 — the cell's 20/20 config fires the anchor zero times in 2 steps).** At `cadence=delay_K=20` the first anchor fire is at tick 20 (≈ global step 10), so a 2-step probe at 20/20 exercises NONE of the new look-ahead code. The probe MUST override anchor latency DOWN so a fire happens early, and run long enough to retain the look-ahead history the fire consumes:
> - `anchor.cadence=1`, `anchor.delay_K=1` (fires every tick), `total_training_steps` set so there are `>= 2*delay_K + 2` optimizer ticks of history before the checked fire — at delay_K=1 this is ~4-6 ticks, i.e. **3-4 global steps** (batch128/mini64 ⇒ 2 ticks/step). Cheap.
> - look-ahead ENABLED, `lookahead_mode=fixed_linear`.
> - The FULL cell stays at 20/20 — the probe latency override is probe-only and never reaches the scored run.
> This probe configuration is what makes the fixed-linear-identity, no-leakage, anchor-isolation, determinism, and backend-integration checks below actually execute against the new code.

The point is to fail fast and cheap on a broken implementation. New code almost always surfaces backend-integration bugs on first launch (sharding / activation-checkpointing / dtype / OOM / autograd). When that happens it is mandatory to iteratively diagnose and FIX it — edit on the `exp/41-*` branch → re-run the fire-forcing probe → repeat — until the invariants pass. Do not stop at the first error. Emit `STUCK:` and halt only as a genuine last resort (a fix needs a design decision or an upstream change). Likely failure surfaces are named in `## Notes for runner`.

### Vast.ai utilization discipline (HARD RULE)
- **One instance for the whole sequence.** Chain A→B→(C) back-to-back on the same box (shared docker / verl checkout / dataset cache / vLLM warm-up). Tearing down + reprovisioning between sequential cells is forbidden. (On-box in-memory rings do NOT persist across the per-cell `python` re-exec — only laptop artifacts transfer; this is fine, each cell rebuilds its own ring.)
- No cell is `parallel_with` another (strict A→B→C dependency), so do not fan out.
- **Tear down the instant the science is captured.** When the last cell that runs (B if it passes, else C) writes `done.flag` and metrics rsync to the laptop, the runner / Stop hook tears down within the next tick. The analyst reads metrics from the laptop, not the box.
- No keep-alive between sessions; state lives in `runs/EXP-41/` on the laptop, not `/workspace/`.
- The fire-forcing correctness-invariant probes run on the SAME box immediately before each cell — they are cheap (~3-4 steps at cadence=1) and must not trigger a separate provision.
