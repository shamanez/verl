## What is already implemented (reuse — do NOT rebuild)
On branch `exp/42-lookahead-horizon` (commits `649594ae` EXP-41, `08bc6d96` EXP-42):
- **Look-ahead weight extrapolation** — for each 2D decoder matrix,
  `θ̂ = (1+α)·θ[t-K] − α·θ[t-2K]` (LayerNorm/embed/lm_head/bias excluded, pass
  through raw stale `θ[t-K]`). Anchor-isolated: no optimizer step / rollout /
  reward / mask. Fire-aligned snapshot ring (`LookaheadSnapshotRing`), no-leak
  asserts, bounded retention.
- **`lookahead_strength` (α)** knob, validated finite ∈ [0,4]. `coeffs =
  (1+α, −α, 0)`. α=1 = AsyncPP seed (2,−1,0) full catch-up; α=0 = raw stale.
- **Two modes**: `fixed_linear` (non-adaptive) and `learned_linear` (adaptive —
  a per-matrix scalar residual `r[name]` cold-started at the fixed coeffs and
  nudged each fire by `r ← clip(r + 0.1·mean(θ_now − θ̂_prev), ±1e-3)`, i.e.
  retrospective error feedback; DP-identical scalar so cross-rank-deterministic).
- **Telemetry**: `anchor_align_cos` (cos of cached anchor grad vs live grad on
  the LIVE batch), `lookahead_source_ticks`, `lookahead_fires`,
  `lookahead_excluded_count`, `lookahead_peak_retained`, learned-coeff
  cross-rank max-rel-dev. Disabled path byte-identical.
- **Capture scaffolding** (`comm_eff.capture`): per-matrix fp32 dumps of
  `G_anchor`, `G_dense`, and a `delay_K=0` fresh-anchor probe grad — available to
  corroborate the new instrument offline.

## What is NEW in this plan (THE deliverable — most important)
A **same-batch, per-matrix gradient-projection-accuracy instrument.** Prior runs
proved projection does not help `val`, but NEVER measured whether the projected
*gradient* is actually more accurate. `anchor_align_cos` cannot answer this — it
compares against `g_live` on a DIFFERENT (live) batch, conflating weight-staleness
with batch-difference. The clean measure holds the batch fixed.

At every anchor fire, on the anchor's OWN stale batch `B = batch[t-K]` (already
loaded), dump-only / detached / NO optimizer effect, compute:
- `g_proj  = g(θ̂; B)`     — the projected anchor grad (already computed in proj runs; == `g_stale` in run 3)
- `g_stale = g(θ[t-K]; B)` — raw-stale reference (extra detached backward at the newest source snapshot)
- `g_now   = g(θ_now; B)`  — target: current live weights (summon + extra detached backward; θ_now is already summoned in learned mode)

Log per fire (overall AND per-matrix over the 196 decoder matrices) to `comm_eff_metrics`:
- `grad_proj_cos  = cos(g_proj,  g_now)`  and  `grad_stale_cos = cos(g_stale, g_now)`
- **`grad_proj_gain = grad_proj_cos − grad_stale_cos`**  ← HEADLINE: is projection making the gradient more accurate?
- `grad_proj_relerr = ‖g_proj−g_now‖/‖g_now‖`  and  `grad_stale_relerr` likewise
- `weight_proj_ratio = ‖θ̂−θ_now‖/‖θ[t-K]−θ_now‖`  (<1 ⇒ weights projected closer in weight space)
- per-matrix distribution: p10 / p50 / p90 of `grad_proj_gain` across the 196 matrices (WHERE projection helps vs hurts)

Cost: +2 detached backwards/fire (proj runs), +1/fire (run 3). ~5 fires over 50
steps ⇒ ~10 extra backwards total. Negligible. Norms are DP-reduced so all
scalars are cross-rank-identical.

## Hypothesis
The look-ahead extrapolation is *intended* to make the K-stale anchor gradient
`g(θ̂)` approximate the current-weight gradient `g(θ_now)`. Falsifiable claim: on
the held-fixed anchor batch, the best non-adaptive (`fixed_linear`, α=0.50) and
best adaptive (`learned_linear`, cold-start 0.50) projectors yield a positive
per-matrix projection gain — **median `grad_proj_gain > +0.02`** — and lower
relative error than the raw-stale anchor; and we quantify whether that accuracy
converts to `val@50` vs the no-projection control. If median `grad_proj_gain ≤ 0`
for both projectors, the premise (linear weight extrapolation → more accurate
gradient) is falsified at the gradient level on this landscape.

## Analyst predicate
- **PASS** iff a projection run shows median `grad_proj_gain > +0.02` AND `val@50 >=` no-projection `val@50` without collapse (projection is BOTH accurate AND useful).
- **REVISE** (<= `iterations`) if projection IS accurate (`grad_proj_gain > +0.02`) but does NOT convert (val <= no-proj or collapses) — name the next knob: `beta_anc` 0.50->{0.25,0.10}, then a shorter horizon α. The mechanistic finding (accurate-but-not-useful) is itself a result.
- **STOP** if median `grad_proj_gain <= 0` for BOTH projection runs — the linear weight extrapolation does NOT translate into a more accurate gradient on this landscape; the projection premise is falsified at the gradient level (the deepest possible finding for this lineage).
- **Pre-run gate**: any `hard`-gate invariant failure => STOP this run; fix on the `exp/*` branch (commit-hotfix loop) and re-probe.
