## Hypothesis

This is an **infra-unit acceptance test** for the shared offline weight-projection
engine (falsifiable, with numeric thresholds — operational thresholds are the
correct falsifiability class for a `kind: analysis` engine-build). The engine —
delivered as `research/scripts/weight_proj_sweep.py` plus a small companion package
under `research/scripts/weight_proj/` — is ACCEPTED iff, streaming the EXP-43
raw-weight trace from R2 (never bulk-downloading it): (1) it implements ALL required
predictor families and reconstructs each from the raw per-snapshot weights —
order-1 fixed and damped, order-2 (3-point Newton forward-difference) and order-3/poly
(Lagrange-Newton over >= 4 points) each with a fixed AND an offline-damped coefficient
source, learnable-at-every-order (BOTH the weak per-matrix scalar residual AND the
strong full-coefficient-vector least-squares), a general learned-regression predictor,
and EMA/momentum (fixed-decay and learnable-decay beta); (2) it computes the FULL
GPU-free metric hierarchy per (family x order x coeff-source x Delta x h) and per
grouping (matrix / block / layer) — `weight_proj_ratio`, `dir_cos`, the
radial/tangential error split, skill `1 - ratio^2`, SNR against the bf16 noise floor,
and the crossover `h*`; (3) it PASSES the bf16-noise-floor sanity gate that REPLACES
the moot on-box-exact parity gate (issue-body supersession — see
`## Background pointers`): a per-block round-trip noise floor is measured, the
manifest fp32-Frobenius cross-check matches within `1e-2` relative, and at the
operating horizons `h >= 5` reported residuals sit above the floor with any (block,h)
at/below the floor FLAGGED `bf16-unreliable` rather than reported as a precise ratio;
(4) it holds the local working set to a bounded footprint (a few in-flight snapshots)
via a single streaming pass that fans out to all block accumulators — no
`aws s3 cp --recursive` of the ~494 GB prefix. FALSIFIED/blocked if any predictor
family cannot be reconstructed as a (linear-or-mildly-nonlinear) combination of the
raw snapshots (it should be — every polynomial extrapolation is a linear combination
of past theta), or if the noise-floor gate cannot be satisfied on the calib grid.

## Correctness invariants (pre-run gate — REQUIRED when `code_change: true`)

Cheap, machine-checkable invariants the analyst verifies FIRST, on a tiny sample of
blocks/ticks, before running the full sweep. A `hard`-gate failure aborts the study
(the engine is broken — fix on the branch and re-probe). All are GPU-free and stream
only a handful of snapshots.

```yaml
invariants:
  - name:  limiting-case identity (order-1, h=0)
    check: "at horizon h=0 every predictor returns theta_stale exactly (theta_hat == theta_stale); weight_proj_ratio(h=0) == 1.0 within 1e-6 for the fixed families"
    gate:  hard
  - name:  predictor reconstruction from raw snapshots
    check: "each fixed/damped/polynomial family's theta_hat, recomputed as an explicit linear combination of the loaded raw snapshots, matches the engine's predict() output within 1e-5 relative on a sample block (proves every family IS reconstructable from the trace — the core falsifier of the hypothesis)"
    gate:  hard
  - name:  manifest fp32-norm cross-check
    check: "for a sample of loaded matrices, recomputed fp32 Frobenius norm matches the manifest fro_norm within 1e-2 relative (reuse research/scripts/verify_full_weight_dump.py — do NOT reinvent)"
    gate:  hard
  - name:  learnable/regression leakage guard
    check: "the learnable (weak scalar + strong full-vector) and general-regression families FIT on a retrospective split and SCORE on strictly-later held-out points; a unit assertion confirms the fit window and the score point never overlap (the classic leakage trap)"
    gate:  hard
  - name:  bounded streaming footprint
    check: "over a >= 10-snapshot streaming pass the local .pt staging directory never exceeds a few in-flight objects (bounded working set); each .pt is deleted right after its per-block slices are extracted; no aws s3 cp --recursive of the prefix"
    gate:  hard
  - name:  grouping integrity
    check: "per-matrix (338), per-block (11 families), and per-layer (28) aggregations sum/partition the 338 matrices exactly — no matrix dropped or double-counted; layer/block labels derive from the manifest names"
    gate:  soft
```

New offline-engine code almost always surfaces I/O + numerics bugs on first run
(R2 cred mapping, bf16↔fp32 cast points, catastrophic cancellation on single-tick
deltas, a leakage window off-by-one, staging-dir leak). When that happens it is
MANDATORY to iteratively diagnose and FIX on the branch → re-run the probe → repeat
until the invariants pass. Likely failure surfaces are named in `## Notes for runner`.
Emit `STUCK:` and halt only as a genuine last resort (a fix needs a design decision —
e.g. a family provably needs fp32 and thus a NEW collection run, not a code fix).

  per-step; per-tick is the finer-Delta, NOISIER (catastrophic-cancellation) regime.

  DIFFERENCES near-equal bf16 tensors; the true per-step update (~1e-3 rel at
  lr=1e-6) is the same order as bf16 rounding (~4e-3). Metrics are reliable for
  cumulative displacement and `h >= ~5`; single-tick/short-horizon deltas carry a
  real floor that SNR must report against, not hide. fp32 is a wired-but-unused
  escape hatch (`dump_dtype=fp32`, ~984 GB) — if a required horizon is
  noise-dominated, that is a NEW fp32 collection run (out of scope), NOT a code fix.
