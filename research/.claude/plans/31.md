## The system we are SIMULATING (the async-realism design constraint — read first)

The fixed `delay_K=5`, lock-step substrate is a **clean simulation** of one pipeline-stage boundary.
The **real decentralized target** is **super-asynchronous**: the **anchor circuit is a single, fixed
set of compute** that serves a **fast SWARM of many instances** over internet links. Shipping
weights/gradients takes variable time, so:

- **The anchor is ALWAYS lagging — never leads.** It is the slow node by construction; it can never
  point ahead of the swarm's current weights. **⇒ delay-compensation / lead / staleness-extrapolation
  levers are RULED OUT** (operator decision 2026-06-15).
- **Staleness is variable / sometimes large / sometimes unknown** (not a fixed 5); fires arrive late,
  jittered, occasionally dropped; instances are heterogeneous.

**Admissibility filter every lever must pass ("does it obey the system?"):**
1. uses the anchor **only as a lagging, trusted reference** (no lookahead, no prediction of future θ);
2. **tolerates variable staleness** — degrades gracefully toward the plain compressed gradient as the
   anchor ages, never blows up;
3. any derived state is **cross-rank / cross-instance identical** (shared codebook — a per-instance
   buffer would diverge the swarm);
4. preserves the **two-circuit structure** (fast compressed swarm + slow stale anchor) — mandatory, it
   is the whole practical-future-use point.

This filter is why the four levers below were chosen and why "make the anchor lead" was dropped.

## The four levers (the tournament) — operator-selected 2026-06-15

Each lever is a *plain idea* + an *update form* + its *async-compat note* + the *beat-dense theory* +
the *new knob* (OFF default = bitwise B2) + the *code surface*. Run cheapest-first.

### L4 — "A pinch of healthy randomness" (zero-mean perturbation) — ALREADY BUILT, run FIRST
- **Idea:** the biased codec-corrected path lost the healthy zero-mean SGD jitter dense has; add a small
  controlled random nudge each step so the model settles into flatter, better-generalizing minima.
- **Form:** `G_corr ← G_corr + σ·‖G_corr‖·ξ`, ξ a unit isotropic Gaussian seeded by
  `hash(perturb_seed, target, step)` ⇒ **cross-rank identical**, fresh per step (zero-mean over training).
- **Beat-dense theory (HEURISTIC, not derived):** SGLD / flat-minima regularization → higher *greedy*
  test accuracy. The nudge is set in RAW-gradient space but AdamW reshapes it per-coordinate before it
  reaches the weights, so σ is not the effective dose; the SGLD/flat-minima story is motivation, not proof.
- **Scope caveat (operator must pick):** the isotropic form is NOT an anchor-usage lever — `ξ=randn`
  touches the anchor nowhere (`_apply_perturbation` draws pure `randn`), so base-L4 is a **regularization
  CONTROL / baseline**, outside the "use the anchor" mandate. The TRUE anchor-shaped lever is the upgrade:
  draw ξ from the recent-δ subspace so the nudge is anchor-shaped. Run isotropic first (free, built) as the
  control; promote to the δ-subspace variant if isotropic shows any signal.
- **Async-compat:** ★★★ trivial — purely local, no anchor comm, no staleness dependence.
- **Knob:** `perturb_sigma` (0.0 = OFF = B2), `perturb_seed`. **Already implemented + CPU-verified** in
  `spectral_filter.py` (`_apply_perturbation`); needs only launcher passthrough + a GPU run.
- **Sweep:** `perturb_sigma ∈ {0.01, 0.03}` (small; σ too large just adds noise).

### L2 — "Build up the corrections" (momentum on δ) — cheap new code
- **Idea:** the compression drops the SAME kind of signal each fire; instead of using each correction
  once, keep a fading running sum so the persistently-missed direction becomes a strong steady push.
- **Form (NORMALIZED EMA — mandatory):** `m ← μ·m + (1−μ)·δ_t`; `G_corr = G_comp + λ·m`. The naive
  `m ← μ·m + δ_t` is FORBIDDEN — its stationary gain is `1/(1−μ)` (μ=0.9 ⇒ **10× dose**) = the constant-λ>1
  amplification dead-end (§FROZEN); it would ignite, get killed, and FALSELY read as "momentum fails." The
  normalized form has stationary gain **1** (a re-weighting, not a louder copy). **Accumulate δ only at
  REFRESH ticks** — δ is HELD between fires in `delayed_ef_matrix`, so accumulating every tick re-adds the
  same δ ~5×; derive + assert the per-step gain before coding.
- **Beat-dense theory:** momentum on the dominant (stable-rank ≈ 2) consistently-missed mode. NOTE dense's
  AdamW ALREADY carries first-moment momentum on its full gradient — L2's claim is narrower: momentum on
  the codec-MISSED direction δ specifically (which dense never separates out), NOT "dense lacks momentum."
- **Async-compat:** ★★ good, with one rule — the buffer is **local** (no extra anchor comm). Because
  fires arrive late/irregularly, **fade each δ by its actual age** (staleness-aware μ) so the buffer decays
  to 0 (G_corr → G_comp) when fires stop. Accumulate the **corrections δ (endogenous, F4: does not pump
  length)**, NEVER the raw M (M-EMA ignited in EXP-27).
- **Knob:** `delta_momentum_mu` (0.0 = OFF = B2) + age-weighting flag. Carrier trip-wires live.
- **Code:** new buffer in `state.py` (CPU fp32, zero-GPU-growth ring style) + the accumulate/read in
  `delayed_ef_matrix`.

### L3 — "Trust the slow node adaptively" (adaptive dose) — cheap new code; uses the unblocked dose
- **Idea:** some steps the cheap gradient agrees with the trusted correction (compression did fine),
  others it disagrees badly (compression dropped a lot). Lean MORE on the correction when they disagree.
- **Form (MEAN-1 CENTERED — mandatory):** `λ_t = 1 + κ·(c̄ − c_t)`, with `c_t` the per-step agreement
  (`cos(G_comp,M)` or `‖δ‖/‖G_comp‖`, both already logged) and `c̄` its running median ⇒ `E[λ_t] ≈ 1`, so
  ONLY the step-to-step DEVIATION is the lever. The naive `λ_t = 1 + κ(1 − cos)` is FORBIDDEN: under THIS
  system's measured geometry `cos(G_comp,M) ≈ 0` (from F1: cos(δ,G_comp_ring)≈−0.95, ‖δ‖/‖G_comp_ring‖≈1.05),
  so it pins at ≈ `1+κ` = constant λ>1 = the ignition dead-end (§FROZEN) — a disguised constant dose, not an
  adaptive one. **Calibrate `c̄` from Cell A's logged cosine distribution (below) BEFORE coding.** `κ=0` ⇒
  `λ_t≡1` ⇒ B2.
- **Beat-dense theory:** spends the trusted signal exactly where the compression hurt most, instead of a
  fixed blunt dose everywhere.
- **Async-compat:** ★★ good — reads only the lagging correction we already hold; just changes HOW MUCH.
  Keep `λ_t` bounded by `lambda_cap` so a stale/garbage M can't spike the dose (variable-staleness safety).
  NOTE the cap bounds RAW λ, not the AdamW-preconditioned step — the ignition trip-wires are the behavioral
  backstop.
- **Knob:** `adaptive_lambda_mode` {off|cos|ratio} + `adaptive_lambda_kappa` (0 = OFF = B2) + `lambda_cap`.
  **Dose-varying ⇒ carrier trip-wires live.**
- **Code:** the gate computation + bounded `λ_t` in `delayed_ef_matrix` (agreement metrics already exist).

### L1 — "Cancel the noise" (batch-difference control variate) — HEAVIEST, run last / GATED
- **Idea:** B2 cancels the *codec* error; L1 additionally tries to cancel *minibatch sampling* noise using
  the anchor gradient M as a baseline. **NOT textbook SVRG:** SVRG's variance reduction comes from a
  full-DATASET snapshot; the anchor's "full coverage" here is full-MATRIX coverage (all 196 matrices) — a
  different axis that does NOT by itself reduce sampling variance. Treat L1 as a **batch-difference control
  variate of UNPROVEN unbiasedness** under GRPO+AdamW, not a guaranteed VR-SGD>SGD win.
- **Form (control variate):** `G_corr = G_comp(θ_t,B_t) − cv·[G_comp(θ_t,B_replay) − M(θ̃,B_replay)]` (the
  bracket shares the replay batch, so it de-noises relative to using B_t alone IFF M and G_comp are actually
  correlated there; `cv=1` recovers the strict form). A cheaper approximate variant recenters the held δ on
  a running compressed-gradient mean. `cv_coeff=0` ⇒ B2.
- **Beat-dense theory (HYPOTHESIS):** IF unbiased AND M correlates with G_comp, variance reduction reaches
  a better optimum at fixed step budget. This is the ONE lever offering something AdamW genuinely lacks
  (Adam rescales per-coordinate; it does NOT reduce sampling variance) — but also the least theoretically
  settled, so measure before trusting.
- **GATE (run L1 only if):** the measured `cov(G_comp, M)` (logged once the L2 branch lands its pre-screen
  scalars, or from Cell A) is non-trivial AND L2/L3 showed signal AND the box is free. Pick `cv_coeff` from
  the measured covariance (≈ cov/var), not blindly.
- **Async-compat:** ★★ good — M is a lagging reference (native to SVRG's stale-snapshot design); degrades
  to plain SGD as M ages. **Cost note (honest):** the strict form needs **one extra local compressed
  backward on the replay batch per step** — extra COMPUTE on the swarm, NOT extra comm (so it still obeys
  the comm-efficiency goal). The approximate recenter variant avoids the extra backward.
- **Knob:** `cv_mode` {off|svrg|recenter} + `cv_coeff` (0 = OFF = B2).
- **Code:** the cross-term plumbing in `transformer_impl.py` (extra replay backward) + `delayed_ef_matrix`.

**Tournament order:** Cell A (B2 reproduce, no code) → **L4** (built, cheapest) → **L2 + L3** (cheap new
code, local) → **L1** (heaviest, gated on the box being free / earlier levers showing signal).

## Live monitoring & early-decision protocol (agent team — operator directive 2026-06-15)

**Every cell is babysat by a two-agent team that takes EARLY decisions — we do not wait for a 50-step
timeout to learn a lever is dead.** Designed to scale to N queued levers (the tournament): each cell gets
the same monitor+analyst+gate treatment; losers are killed early so GPU spends on winners.

- **`training-log-monitor`** (one per live cell, 30 s cadence): SSH-polls tmux liveness + done flags,
  greps Traceback / Ray-unhandled / OOM / NaN, runs per-GPU `nvidia-smi` (sustained idle while tmux
  ALIVE = stall → flag immediately, don't wait for timeout), fetches the cell's WandB scalars, rsyncs
  artifacts as vals land. Returns done/dead/stall/error for the orchestrator.
- **`analyst`** applies the PRE-REGISTERED go/no-go at the two val checkpoints (test_freq=25 ⇒ val@0
  is the pre-train probe, val@25 the first real read, val@50 the headline):

```yaml
early_decisions:                       # B2_live = the Cell-A reproduction on THIS box (substrate control)
  - at: val@25
    KILL_EARLY  if: "val@25 < (B2_live@25 − 0.03)  AND  train reward-mean slope ≤ 0 over the last ~10 steps"
                    # the lever is not helping → stop the cell, free the box for the next lever
    CONTINUE    if: "val@25 ∈ [B2_live@25 − 0.03, +∞)"            # in-band or better → run to 50
    FLAG        if: "any ignition trip-wire (P1/P2/P3/E1, below) → STOP + post STUCK note"
  - at: val@50
    EXTEND_TO_100 if: "val@50 clears B2_live@50 beyond +0.024  (confirm the gain holds past B2's decay)"
    BANK_AND_NEXT if: "val@50 ∈ parity band (within ±0.024 of B2_live@50)"   # record, move to next lever
    KILL          if: "val@50 < B2_live@50 − 0.024"                          # NULL for this lever
ignition_trip_wires (dose/buffer cells — EXP-27 carrier watch, BACK ON):
  P1: ≥2 consecutive response_length cap-pins (len/max ≈ 16384)
  P2: response_length mean slope > 0 sustained (climbing, not flat)
  P3: response_length mean > 2× its early-training value
  E1: early gate — len/max > 4000 at steps 10–30
```

The example the operator gave is exactly this loop: *at val@25, what is happening? at val@50, is there a
real jump or should we kill it and try the next method?* — answered by a standing rule, not ad-hoc.
